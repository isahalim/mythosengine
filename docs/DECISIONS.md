## 2026-08-27 (later night) — tts-edge.ts: subprocess to a Python wrapper, not a hand-rolled protocol or an npm import

**What changed:** implemented `src/lib/drivers/tts-edge.ts` + `scripts/edge_tts_synth.py`. The driver shells out to the wrapper script (`node:child_process.execFile`), which imports the `edge_tts` Python library (LGPL-3.0, `rany2/edge-tts`) directly and requests `WordBoundary` events explicitly. Real end-to-end smoke test passed: real audio bytes + real word-level timings (`startMs`/`endMs` per word) from the live, unauthenticated Microsoft endpoint. 6 contract tests against fixture Python scripts (success, malformed JSON, missing output files, non-zero exit/retry, hang/timeout, missing interpreter).

**Why, and what was rejected — this took three iterations before landing on the actual implementation:**

1. **Rejected: hand-rolling the WebSocket protocol in TypeScript**, as `ARCHITECTURE.md` originally implied ("speaks the underlying protocol directly"). Research turned up that Microsoft rotates a `Sec-MS-GEC` auth token derived from the Chromium version on every Edge release, and the reference Python project runs a *daily CI job* just to detect when it's gone stale. Reimplementing that from scratch in one session, with no ongoing maintenance capacity, would have shipped a driver that quietly breaks the first time Microsoft ships a new Edge build.
2. **Rejected: importing a JS port as an npm dependency** (`edge-tts-universal`, `@andresaya/edge-tts`, `@travisvn/edge-tts`) — checked their licenses before adding any of them (same `npm view`-style diligence as every other dependency) and found every JS port of this library is AGPL-3.0 or GPL-3.0. That's a real, consequential licensing decision — copyleft obligations, especially AGPL's network-use clause, aren't something to pull into a dependency tree silently on the operator's behalf.
3. **What was actually built:** the original Python `edge_tts` library is LGPL-3.0 — meaningfully weaker copyleft, and more to the point, invoking it as a **separate OS process** (not a code import) sidesteps the linking question for the TypeScript codebase entirely, under any reading of any of these licenses. This is exactly the same pattern already established for `yt-dlp` and `ffmpeg` — Python/native CLI tools invoked via `child_process`, never imported. `scripts/edge_tts_synth.py` exists specifically because the bare `edge-tts` CLI hard-codes sentence-level subtitle boundaries with no flag to select word-level (confirmed by actually running it and reading the library source — the CLI's SentenceBoundary default surprised me, ARCHITECTURE.md originally assumed word-level was the default output). The 30-line wrapper script calls the library's `Communicate` class directly with `boundary="WordBoundary"` instead.

`ARCHITECTURE.md` §0/§5.6, `CLAUDE.md`'s stack list, and `AGENT_PLAYBOOK.md`'s Phase 1 task were all updated to describe what was actually built, not the original guess.

## 2026-08-27 (night) — Phase 2: data layer

**What changed:** implemented `ARCHITECTURE.md` §4 with Drizzle (`db/schema.ts`), generated the initial migration (`db/migrations/0000_*.sql`), and wrote `src/lib/state.ts` (explicit transition maps for `signals`/`scripts`/`renders`/`uploads`, throwing `IllegalTransitionError` on anything not listed — e.g. skipping a stage or leaving a terminal state). 63 tests passing, including: every CHECK constraint proven to reject an illegal value at the DB layer (not just through the ORM), an idempotent-insert test proving a retried `signals` insert yields one row, a real transaction-rollback test, and `db/footage-select.ts`'s `claimNextFootageSegment` — the atomic single-`UPDATE...RETURNING` operation the rotation guarantee in `ARCHITECTURE.md` §9 depends on.

**Why:** `pnpm verify`'s own gate demanded it (Task 0.3's coverage/lint/secret-scan bar), and the state machine exists because `renders`/`uploads` illegal transitions are exactly the kind of bug that reads as "the channel published something it shouldn't have" after the fact.

**What was rejected:**
- **Drizzle's `text(..., { enum: [...] })` alone** — it's TypeScript-only, does not emit a SQL `CHECK` constraint (confirmed by inspecting the generated migration before adding explicit `check()` calls). Relying on it alone would have meant illegal states were only prevented through the ORM, not the database — directly against `ARCHITECTURE.md`'s own stated rationale for using CHECK constraints at all. Every enum-shaped column now has both.
- **`drizzle-orm/node-sqlite`** — this import doesn't exist in the installed `drizzle-orm@0.45.2`; a web search result had conflated a third-party community package (`yjl9903/drizzle-sqlite`) with official Drizzle support for Node's built-in `node:sqlite`. Caught by actually trying the import and checking the package's real `exports` map rather than trusting the search summary. Used `better-sqlite3` instead (devDependency only — production reads/writes D1, never this) — it's the standard, well-established choice for local Drizzle+D1 development and every official Drizzle+D1 guide uses it.
- **A real multi-threaded concurrency test for `claimNextFootageSegment`** — Node's single-threaded and `better-sqlite3` is synchronous, so true interleaving can't be reproduced in a unit test. The correctness argument is structural instead: the claim is one `UPDATE ... WHERE id = (SELECT ...) RETURNING`, so there's no read-then-write window for a second caller to race into, regardless of what a timing-based test could or couldn't prove.
- Kept the esbuild@0.18.20 fix as a `pnpm-workspace.yaml overrides` entry rather than waiting on drizzle-kit to update its bundled `esbuild-kit` dependency — `osv-scanner` caught the real, current GHSA-67mh-4wv8-2f99 finding; verified `drizzle-kit generate` still works against the overridden version before accepting the fix.

## 2026-08-27 (evening) — Project pivot: MythosEngine → AutoShorts AI

**What changed:** the entire product direction. `CLAUDE.md`, `PROVISIONED.md`, `ARCHITECTURE.md`, `AGENT_PLAYBOOK.md`, and `CONSOLE_SPEC.md` were rewritten from a game-news publishing site to an autonomous YouTube Shorts pipeline (trend ingestion → scripted narration → gameplay footage → TTS + captions → FFmpeg render → policy gate → YouTube upload), at the operator's explicit direction. Same repo, same Cloudflare Worker (`mythosengine` — kept as the technical name; the product is branded AutoShorts AI in the console only), same driver-abstraction philosophy, same verify gate. `.mcp.json` gained an `edge-tts-mcp` entry (`uvx edge_tts_mcp`, verified against PyPI, not guessed).

**Why:** operator's explicit request to redirect the project. Three consequential decisions were resolved via clarifying questions before writing anything, because they're genuinely hard to reverse once code depends on them:

1. **Footage sourcing.** Literally "download trending game gameplay" means scraping other creators' videos — real copyright exposure regardless of transformation. Operator's resolution: source from long-form walkthrough/guide creators specifically (their content functions more like movies/guides, arguably strengthening a transformative-use position), scraped **weekly** (not per-render) to find each tracked channel's current most-watched video, clip different random high-action segments from the same source video across many renders. This is now `footage_sources`/`footage_segments` + the weekly FOOTAGE REFRESH stage (`ARCHITECTURE.md` §5.0). **Stated plainly, not downplayed:** downloading the source video via `yt-dlp` is itself a YouTube ToS matter, separate from whether the resulting heavily-cropped, narrated, captioned clip is transformative enough to be defensible. Isolating this to one weekly, low-volume, fully-audited job (never inline in the daily render) is the mitigation chosen here — not a claim of zero risk. If a strike or takedown ever happens, start the postmortem at this stage.
2. **TTS provider.** Operator chose Microsoft Edge's unofficial "Read Aloud" TTS (the same protocol the `edge-tts` library and `edge-tts-mcp` wrap) over Inworld, specifically for its $0 permanent cost. Traded off against MythosEngine's old "prime directive: permanent free tier" — this qualifies, but it's an unofficial API with no SLA, not a contractual free tier. The driver-abstraction pattern exists precisely so a paid fallback is one new file + one env var if Microsoft ever closes it off; `ARCHITECTURE.md` §0/§9 calls this out as a reliability risk to alert on, not a cost risk to budget for.
3. **YouTube policy-suspension risk.** Current (2025-renamed) "inauthentic content" policy explicitly three-strikes mass-produced/templated/reused-visual channels — close to a literal description of the naive version of this pipeline. Operator chose to bake in an explicit POLICY GATE (`ARCHITECTURE.md` §9): an originality-score floor from an adversarial critic pass, footage rotation tracking so the same clip doesn't repeat, script-similarity checks against upload history, and the synthetic-media disclosure flag on every upload. Mirrors MythosEngine's citation-verification gate — same "the model never publishes/uploads, a deterministic check decides" philosophy, redirected at a different risk.

MCP clarification worth recording since it's a recurring source of confusion: "MCP-compatible TTS" was interpreted as *"give the coding agent a way to test TTS during development,"* not *"the deployed pipeline calls an MCP server at runtime."* The latter isn't how MCP is meant to be used — it's an agent-tool protocol, not a backend integration pattern. `src/lib/drivers/tts-edge.ts` (Phase 1, not yet written) will speak the underlying protocol directly, matching every other driver's shape.

**What was rejected:**
- **Inworld TTS** — confirmed via research to have no recurring free tier (one-time ~40-70 min trial, then $15-35/million characters, roughly $2-5/month at this project's volume). Not expensive, but it broke the "permanent, card-free" test Edge TTS passes. Kept as the obvious first fallback if Edge TTS ever dies — the interface (`TtsDriver`) doesn't care which one is behind it.
- **A live per-run scraper with no maintained library** — the operator's actual answer (weekly refresh into a library) already avoids this; recorded here because it was the more dangerous alternative that was explicitly steered away from during the design conversation.
- **Cloudflare R2 for the footage library** — still requires a card to activate even on the free tier (same finding as MythosEngine's original v1.0→v1.1 revision). A git orphan branch holding only short, already-transformed clips (not full source videos) fits the "small rotating library" use case without reopening that constraint.
- Renaming the Worker/repo to match the new product name — infra churn for a cosmetic change; the product is branded AutoShorts AI in the console UI, the technical substrate keeps its existing name.
