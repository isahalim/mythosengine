## 2026-08-28 (afternoon) — Phase 5: footage pipeline, first real end-to-end proof of the full chain

**What changed:** implemented FOOTAGE REFRESH end to end: `src/lib/drivers/youtube-search.ts` (+ `iso8601-duration.ts`), `src/lib/footage/{motion-score,clip,library,refresh}.ts`. Full technical detail in `AGENT_PLAYBOOK.md`'s Phase 5 entry.

**Why the motion-scoring approach is what it is:** verified ffmpeg's `signalstats`+`metadata=print` output format against a real invocation before writing the parser (a `frame:N pts_time:T` header followed by `key=value` lines, including `lavfi.signalstats.YDIF/UDIF/VDIF` — per-channel frame-to-frame difference). Sliding a window across the resulting per-second series and picking non-overlapping high-motion peaks is a standard, simple motion proxy — not a claim of detecting "excitement" or "action" in any perceptual sense, just frame-to-frame pixel change, which is honest and good enough to rank candidates.

**A real environment problem found and fixed along the way, not just software:** installing `ffmpeg-full` earlier (for the Phase 1 render-driver's real caption-burn-in test) left the plain Homebrew `ffmpeg` binary dynamically linked against an x265 library version that `brew`'s cleanup had since removed — the default `ffmpeg` on this machine's PATH silently stopped working. Found via a real test failure, not assumed; fixed with `brew reinstall ffmpeg` (relinks against current dependencies), verified working again, and the full suite was rerun to confirm.

**What was rejected:**
- **A perceptual "action" classifier** (motion detection via optical flow, object detection, or anything ML-based) for scoring candidate windows — `signalstats`' frame-difference metric is simpler, needs no additional model or dependency, and is transparent about what it actually measures. Revisit if simple frame-difference ever proves to pick bad clips in practice.
- **A real live run of `youtube-search.ts`** — no `YOUTUBE_API_KEY` exists yet (not provisioned, see `PROVISIONED.md`). Contract-tested only, same honest gap as `upload-youtube.ts`'s missing OAuth smoke test.
- **Pushing the `assets-library` branch to a remote as part of `commitClipToLibrary`** — deliberately out of scope for this function. Committing locally is safe and idempotent to retry; pushing is an action visible to others and stays a separate, explicit step (the actual GitHub Actions workflow's job, when Phase 8 wires it, not a driver's).

## 2026-08-28 (midday) — First footage_sources entry: HollowPoiint; TubePull kept dev-time only

**What changed:** `data/footage_sources.yml` seeded with `@HollowPoiint` (confirmed real: 3.2M subscribers, full-game walkthroughs including GTA V — matches the "long-form guide/movie-style" criteria `ARCHITECTURE.md` §5.0 was written around) at the operator's direction. `.mcp.json` gained a `tubepull` entry.

**Why TubePull is dev-time only, not the production download path:** the operator suggested it specifically because its free tier caps at 3 downloads/day, which "fits" the weekly refresh job's low volume. That's a real observation, but it doesn't outweigh what TubePull actually is: a third-party hosted service that runs the download on *its own* infrastructure and hands back a signed link — built and marketed for interactive AI-assistant use (Claude/ChatGPT/Perplexity/Cursor), not documented or obviously intended for a headless cron job. Weighed against `download-ytdlp.ts`, which is already built, contract-tested, **and proven against a live YouTube URL in this session** (Phase 1): TubePull adds a business-continuity dependency (a free hosted service that could shut down, reprice, or change its tool schema with no notice — worse than `edge-tts`'s "unofficial but at least self-hostable" risk profile, since TubePull isn't open source and can't be forked if it disappears) and an external rate limit our own driver doesn't have, in exchange for no capability we didn't already have working. Presented this tradeoff to the operator directly rather than deciding silently; they agreed.

**What TubePull is kept for:** quick manual `get_video_info`/preview checks on a candidate video during development, the same "dev-time convenience, not a runtime dependency" role `edge-tts-mcp` already has in this project.

**What was rejected:** rewiring the weekly FOOTAGE REFRESH job to call TubePull instead of `yt-dlp` — would have replaced a proven, self-hosted, already-tested driver with a rate-limited third-party service for no functional gain.

## 2026-08-28 (morning) — Phase 3: trend ingestion, and Reddit's real access terms

**What changed:** implemented WATCH + SCORE (`src/lib/ingest/{feed-parser,watch,simhash,score,seed-sources}.ts`), seeded `data/sources.yml`, added `etag`/`last_modified` to `sources` (migration `0001`). Full details of what was built are in `AGENT_PLAYBOOK.md`'s Phase 3 entry. This entry is specifically about the Reddit-sourcing finding, since it changed the plan mid-implementation.

**What was found:** the original plan (`AGENT_PLAYBOOK.md`, written during the pivot) assumed "3-5 subreddits' `.json` feeds" the same way MythosEngine's old WATCH stage assumed zero-key Reddit access. Testing that assumption before building on it turned up two independent problems:
1. Reddit's `www.reddit.com/r/*/.json` and even the plain HTML pages returned HTTP 403 from this session's network — a wholesale IP-range block, not a per-request issue (`example.com` worked fine from the same network in the same test).
2. Separately, and more durably (this doesn't depend on which IP a runner happens to have): Reddit's Data API free tier is explicitly non-commercial-use only as of 2026. This project is a monetized YouTube channel. Even from an IP Reddit doesn't block, using the JSON API here would likely be outside the free tier's actual terms.

**What was built instead:** subreddit public RSS/Atom syndication feeds (`reddit.com/r/<sub>/hot.rss`) — confirmed reachable from the same blocked network, and a different Reddit product with different (much more permissive, standard-syndication) terms, not the Data API this project can't freely use. Treated identically to any other RSS source — no separate "reddit" driver needed, `kind='rss'` covers it. Traded off: no real engagement numbers (upvotes/comment counts aren't in the Atom payload, confirmed by inspecting a real feed entry) — `SCORE` uses feed rank position (subreddit feeds are pre-sorted by "hot") plus cross-source corroboration count instead of real vote counts. Honest proxy, not real data pretending to be real data.

**What was rejected:**
- Silently keeping the original ".json feeds" plan and hoping it would work in GitHub Actions even though it failed here — GH Actions runners are also well-known datacenter IP ranges; there was no reason to expect a different result, and the commercial-terms problem doesn't depend on IP at all.
- A Reddit OAuth "installed app" flow to get past the block — technically possible, but doesn't resolve the commercial-use terms question, and adds a credential/vault entry for a source this project can cover for free another way. Worth reconsidering if Reddit's RSS feeds ever get shut off too.
- Fixed a real bug in `src/lib/drivers/http.ts` discovered while building conditional-GET support: `fetchWithRetry` treated HTTP 304 as an error (`Response.ok` is `false` for 304, not in the 200-299 range `fetchWithRetry` checked). Every future conditional-GET caller would have silently misreported a cache hit as a failure. Not rejected — fixed, regression-tested, and the full suite was rerun to confirm no other driver's retry/error behavior changed as a side effect.

## 2026-08-27 (very late) — render-ffmpeg.ts, with a real caption burn-in proof

**What changed:** implemented `src/lib/drivers/ass-subtitles.ts` (pure function, no ffmpeg needed to test it — builds an ASS subtitle track from timed caption cues, bold/outlined/centered, each cue fading in and out) and `src/lib/drivers/render-ffmpeg.ts` (shells out to `ffmpeg`/`ffprobe`; loops the footage segment with `-stream_loop -1` + `-shortest` so a 15-30s clip correctly covers a ~60s narration track; crops/scales with `force_original_aspect_ratio=increase` + `crop` to fill the entire 1080x1920 frame; mutes the source by simply never mapping its audio stream). 5 contract tests against fixture `ffmpeg`/`ffprobe` scripts, plus a real render: real narration audio + real word timings from `tts-edge.ts`'s smoke test, a synthetic 2-second test-pattern clip deliberately shorter than the 4.6s narration (to force real looping, not a no-op), real ASS caption burn-in. Not a mocked assertion; an actual image was inspected.

**Why:** ARCHITECTURE.md §5.7 and the operator's own reference screenshot specify this exact style — full-bleed cropped gameplay, bold captions, no static subtitle box — and "the render driver produces a file" is a much weaker claim than "the render driver produces a file that looks right," so this was worth actually looking at rather than trusting exit code 0.

Installed `ffmpeg-full` (a bottled, prebuilt Homebrew formula that includes `libass` and 46 other codec/filter dependencies) instead of the much slower `brew install --build-from-source ffmpeg`. This is a local development-environment note, not a project dependency change — the driver still defaults to a bare `"ffmpeg"` on `PATH`, configurable. **Flagged, not yet confirmed:** GitHub Actions' `ubuntu-latest` ffmpeg (installed via `apt`) very likely includes `libass` by default, but that needs an actual check when Phase 6 wires this into a real workflow, not an assumption carried over from "it worked on the operator's Mac after a different install."

**What was rejected:** `drawtext`-per-word as a libass-free fallback — would have avoided the local environment problem entirely, but produces meaningfully worse output (no native fade transitions, one filter chain entry per cue gets unwieldy past a few dozen words, no karaoke/style primitives) for a caption style the operator specifically referenced. Not worth degrading the actual product to dodge a one-time local `brew install`.

## 2026-08-27 (later night) — tts-edge.ts: subprocess to a Python wrapper, not a hand-rolled protocol or an npm import

**What changed:** implemented `src/lib/drivers/tts-edge.ts` + `scripts/edge_tts_synth.py`. The driver shells out to the wrapper script (`node:child_process.execFile`), which imports the `edge_tts` Python library (LGPL-3.0, `rany2/edge-tts`) directly and requests `WordBoundary` events explicitly. Real end-to-end smoke test passed: real audio bytes + real word-level timings (`startMs`/`endMs` per word) from the live, unauthenticated Microsoft endpoint. 6 contract tests against fixture Python scripts (success, malformed JSON, missing output files, non-zero exit/retry, hang/timeout, missing interpreter).

**Why, and what was rejected — this took three iterations before landing on the actual implementation:**

1. **Rejected: hand-rolling the WebSocket protocol in TypeScript**, as `ARCHITECTURE.md` originally implied ("speaks the underlying protocol directly"). Research turned up that Microsoft rotates a `Sec-MS-GEC` auth token derived from the Chromium version on every Edge release, and the reference Python project runs a *daily CI job* just to detect when it's gone stale. Reimplementing that from scratch in one session, with no ongoing maintenance capacity, would have shipped a driver that quietly breaks the first time Microsoft ships a new Edge build.
2. **Rejected: importing a JS port as an npm dependency** (`edge-tts-universal`, `@andresaya/edge-tts`, `@travisvn/edge-tts`) — checked their licenses before adding any of them (same `npm view`-style diligence as every other dependency) and found every JS port of this library is AGPL-3.0 or GPL-3.0. That's a real, consequential licensing decision — copyleft obligations, especially AGPL's network-use clause, aren't something to pull into a dependency tree silently on the operator's behalf.
3. **What was actually built:** the original Python `edge_tts` library is LGPL-3.0 — meaningfully weaker copyleft, and more to the point, invoking it as a **separate OS process** (not a code import) sidesteps the linking question for the TypeScript codebase entirely, under any reading of any of these licenses. This is exactly the same pattern already established for `yt-dlp` and `ffmpeg` — Python/native CLI tools invoked via `child_process`, never imported. `scripts/edge_tts_synth.py` exists specifically because the bare `edge-tts` CLI hard-codes sentence-level subtitle boundaries with no flag to select word-level (confirmed by actually running it and reading the library source — the CLI's SentenceBoundary default surprised me, ARCHITECTURE.md originally assumed word-level was the default output). The 30-line wrapper script calls the library's `Communicate` class directly with `boundary="WordBoundary"` instead.

`ARCHITECTURE.md` §0/§5.6, `CLAUDE.md`'s stack list, and `AGENT_PLAYBOOK.md`'s Phase 1 task were all updated to describe what was actually built, not the original guess.

**What changed:** implemented `ARCHITECTURE.md` §4 with Drizzle (`db/schema.ts`), generated the initial migration (`db/migrations/0000_*.sql`), and wrote `src/lib/state.ts` (explicit transition maps for `signals`/`scripts`/`renders`/`uploads`, throwing `IllegalTransitionError` on anything not listed — e.g. skipping a stage or leaving a terminal state). 63 tests passing, including: every CHECK constraint proven to reject an illegal value at the DB layer (not just through the ORM), an idempotent-insert test proving a retried `signals` insert yields one row, a real transaction-rollback test, and `db/footage-select.ts`'s `claimNextFootageSegment` — the atomic single-`UPDATE...RETURNING` operation the rotation guarantee in `ARCHITECTURE.md` §9 depends on.

**What was rejected:**
- **Drizzle's `text(..., { enum: [...] })` alone** — it's TypeScript-only, does not emit a SQL `CHECK` constraint (confirmed by inspecting the generated migration before adding explicit `check()` calls). Relying on it alone would have meant illegal states were only prevented through the ORM, not the database — directly against `ARCHITECTURE.md`'s own stated rationale for using CHECK constraints at all. Every enum-shaped column now has both.

Caught by actually trying the import and checking the package's real `exports` map rather than trusting the search summary. Used `better-sqlite3` instead (devDependency only — production reads/writes D1, never this) — it's the standard, well-established choice for local Drizzle+D1 development and every official Drizzle+D1 guide uses it.
- **A real multi-threaded concurrency test for `claimNextFootageSegment`** — Node's single-threaded and `better-sqlite3` is synchronous, so true interleaving can't be reproduced in a unit test. The correctness argument is structural instead: the claim is one `UPDATE ... WHERE id = (SELECT ...) RETURNING`, so there's no read-then-write window for a second caller to race into, regardless of what a timing-based test could or couldn't prove.
- Kept the esbuild@0.18.20 fix as a `pnpm-workspace.yaml overrides` entry rather than waiting on drizzle-kit to update its bundled `esbuild-kit` dependency — `osv-scanner` caught the real, current GHSA-67mh-4wv8-2f99 finding; verified `drizzle-kit generate` still works against the overridden version before accepting the fix.

## 2026-08-27 (evening) — Project pivot: MythosEngine → AutoShorts AI

**What changed:** the entire product direction. `CLAUDE.md`, `PROVISIONED.md`, `ARCHITECTURE.md`, `AGENT_PLAYBOOK.md`, and `CONSOLE_SPEC.md` were rewritten from a game-news publishing site to an autonomous YouTube Shorts pipeline (trend ingestion → scripted narration → gameplay footage → TTS + captions → FFmpeg render → policy gate → YouTube upload), at the operator's explicit direction. Same repo, same Cloudflare Worker (`mythosengine` — kept as the technical name; the product is branded AutoShorts AI in the console only), same driver-abstraction philosophy, same verify gate. `.mcp.json` gained an `edge-tts-mcp` entry (`uvx edge_tts_mcp`, verified against PyPI, not guessed).

**Why:** operator's explicit request to redirect the project. Three consequential decisions were resolved via clarifying questions before writing anything, because they're genuinely hard to reverse once code depends on them:

1. **Footage sourcing.** Literally "download trending game gameplay" means scraping other creators' videos — real copyright exposure regardless of transformation. Operator's resolution: source from long-form walkthrough/guide creators specifically (their content functions more like movies/guides, arguably strengthening a transformative-use position), scraped **weekly** (not per-render) to find each tracked channel's current most-watched video, clip different random high-action segments from the same source video across many renders. This is now `footage_sources`/`footage_segments` + the weekly FOOTAGE REFRESH stage (`ARCHITECTURE.md` §5.0). **Stated plainly, not downplayed:** downloading the source video via `yt-dlp` is itself a YouTube ToS matter, separate from whether the resulting heavily-cropped, narrated, captioned clip is transformative enough to be defensible. Isolating this to one weekly, low-volume, fully-audited job (never inline in the daily render) is the mitigation chosen here — not a claim of zero risk. If a strike or takedown ever happens, start the postmortem at this stage.
2. **TTS provider.** Operator chose Microsoft Edge's unofficial "Read Aloud" TTS (the same protocol the `edge-tts` library and `edge-tts-mcp` wrap) over Inworld, specifically for its $0 permanent cost. Traded off against MythosEngine's old "prime directive: permanent free tier" — this qualifies, but it's an unofficial API with no SLA, not a contractual free tier. The driver-abstraction pattern exists precisely so a paid fallback is one new file + one env var if Microsoft ever closes it off; `ARCHITECTURE.md` §0/§9 calls this out as a reliability risk to alert on, not a cost risk to budget for.
3. **YouTube policy-suspension risk.** Current (2025-renamed) "inauthentic content" policy explicitly three-strikes mass-produced/templated/reused-visual channels — close to a literal description of the naive version of this pipeline. Operator chose to bake in an explicit POLICY GATE (`ARCHITECTURE.md` §9): an originality-score floor from an adversarial critic pass, footage rotation tracking so the same clip doesn't repeat, script-similarity checks against upload history, and the synthetic-media disclosure flag on every upload. Mirrors MythosEngine's citation-verification gate — same "the model never publishes/uploads, a deterministic check decides" philosophy, redirected at a different risk.

MCP clarification worth recording since it's a recurring source of confusion: "MCP-compatible TTS" was interpreted as *"give the coding agent a way to test TTS during development,"* not *"the deployed pipeline calls an MCP server at runtime."* The latter isn't how MCP is meant to be used — it's an agent-tool protocol, not a backend integration pattern. `src/lib/drivers/tts-edge.ts` (Phase 1, not yet written) will speak the underlying protocol directly, matching every other driver's shape.

**What was rejected:**
- **Inworld TTS** — confirmed via research to have no recurring free tier (one-time ~40-70 min trial, then $15-35/million characters, roughly $2-5/month at this project's volume). Not expensive, but it broke the "permanent, card-free" test Edge TTS passes. Kept as the obvious first fallback if Edge TTS ever dies — the interface (`TtsDriver`) doesn't care which one is behind it.
- **A live per-run scraper with no maintained library** — the operator's actual answer (weekly refresh into a library) already avoids this; recorded here because it was the more dangerous alternative that was explicitly steered away from during the design conversation.
- **Cloudflare R2 for the footage library** — still requires a card to activate even on the free tier (same finding as MythosEngine's original v1.0→v1.1 revision). A git orphan branch holding only short, already-transformed clips (not full source videos) fits the "small rotating library" use case without reopening that constraint.
- Renaming the Worker/repo to match the new product name — infra churn for a cosmetic change; the product is branded AutoShorts AI in the console UI, the technical substrate keeps its existing name.
