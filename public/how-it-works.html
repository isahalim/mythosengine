Autonomous video production · one operator

It reads the argument
of the day and shatters
it into a video.

Mythos Engine watches what the internet is arguing about, researches it against real sources, writes a short opinionated script, finds footage that actually illustrates the point, and renders a finished vertical video with narration, animated captions and an animated host. Then it stops — and hands the whole thing to a human to look at.

3 videos a day, at most ~130s typical runtime 0 automatic uploads 12 stages per render 2 model providers, on purpose

What it's for

A studio that runs itself, and still asks permission.

Making a good short video is about six jobs — noticing a story, checking it, writing it, shooting it, cutting it, packaging it. Each one is small. Doing all six, three times a day, forever, is not. This system does the six jobs and leaves the seventh — deciding whether the thing is good enough to publish — to a person.

It notices

Every hour it reads public discussion feeds — Reddit, news, YouTube — and scores what's rising: how fast a conversation is growing, how new it is, and whether it's just a repeat of something from last week.

It builds

A run turns one story into a finished 1080×1920 video: researched, scripted, performed, shot, cut, captioned and hosted. It takes minutes and costs a few cents of model usage.

It shows its work

Nothing ships without a paper trail: the script, the critic's verdict, every clip's source and the exact seconds used, which voice spoke it, and which model answered every thinking step.

RULE There is no publish button anywhere in this system. It holds no YouTube upload credential and calls no upload endpoint. The last mile — watching the video, reading the sheet, pasting the title — is deliberately human, because the channel carries a real person's name.

Architecture

Two machines, and a clean line between them.

A tiny always-on web service holds the state and the steering. A heavy build machine does the video. Nothing on the web side ever calls a model or touches a video file — that split is what keeps the interactive surface instant and the expensive work interruptible.

Always on · the control surface

One Cloudflare Worker

Serves the whole app and its API from one place. Behind it: D1 (a SQL database) for state, KV for hot JSON and the encrypted key vault, and R2 for finished video files, which are 40–60 MB and too big for anything else. Sign-in is a passkey — no password exists.

It makes no model call at all. Not one. Every screen it draws comes from the database or from plain code.

On demand · the build machine

A GitHub Actions runner

Cloudflare can't run FFmpeg or start a subprocess, so the render happens on a real machine with FFmpeg, Python and yt-dlp installed. The operator presses a button; the Worker starts the job and hands it a trace id; the job reports each stage back into the same database the console reads.

Every model call in the product happens here, inside the render — never in the browser, never in the Worker.

The operator surface

One page, six stages, made of broken glass.

The console isn't a dashboard that reports what happened. It's a workspace that decides what happens next: how many videos this run makes, what each one is about, and which story each one tells. It's a single continuous surface — shattered glass over drifting colour — rather than a set of pages.

Stage 1

The landing

Sign in with a passkey. Scroll, and sixteen glass fragments assemble into one sealed pane with a real finished video inside it. Click to crack it; click again to play.

Stage 2

How many

Light one shard per video you want from this run. The number of glows is the number of videos.

Stage 3

Topics

Each lit shard fuses with a new one and takes a topic colour — viral, politics, tech, science, AI, philosophy, concept.

Stage 4

Ideas

A bigger shard joins each video carrying its story, chosen from a live-scored list of what's being argued about right now.

Stage 5

Agents deployed

The run starts. Each video's pane heals as its stages complete — you watch the glass reassemble in real time.

Stage 6

Review

Play it in place, read the upload sheet, check every clip's source, download it, mark it reviewed — or throw it away and run it again.

FRESH The Ideas list is current the moment you open it, and no model orders it. Opening stage 4 re-reads the feeds — one source per host, rotating, with no retries, because Reddit serves roughly one request per IP per 30–60 seconds. Ranking blends keyword match with a 12-hour recency half-life, so a story ingested seconds ago outranks a week-old one it barely beats on wording.

The pipeline, stage by stage

What actually happens between a headline and a video.

Everything below follows one worked example: a rising thread about a publisher revoking access to games people had already paid for. The examples are illustrative and abbreviated, but the prompts, tools, models and rules are the real ones.

01 Watch
plain code · no modelhourlyRSS

Read the feeds, keep what's new

A list of sources lives in a file in the repo, and the database follows the file rather than the other way round. Each source is a public syndication feed — subreddits, news outlets — fetched with a real browser identity and a hard timeout. Everything found becomes a “signal”: a title, a summary, a source, a timestamp.

One deliberate detail: the feeds are rising.rss, not hot.rss. A “hot” feed's newest item measured about four hours old — proven discourse, but not what's being argued about right now, which is the whole point of the screen it feeds.

Example signal as stored
source  reddit-gaming · https://reddit.com/r/gaming/rising.rss
title   "They revoked my licence to a game I bought in 2019"
summary Thread arguing about whether a purchase is a purchase when
        the storefront can withdraw the licence years later.
seen    2026-09-03T09:14:22Z   status observed

Which of these is worth a video

Signals are ranked on how fast the conversation is growing and how fresh it is, then checked against the last seven days with a similarity fingerprint so the channel doesn't make the same video twice under two headlines. When the operator turns on diversity mode, the day's picks are actively spread across different sources instead of all coming from whichever feed is loudest.

03 Research
gemini-3.7-flash → openai/gpt-oss-120b2 toolsBM25 + rerankfails soft

Find out what's actually being said

Before anything is written, the model builds a short factual brief — what happened, what people are arguing, and which retrieved source backs each claim. It is told, in as many words, that the retrieved material is everything it knows: an angle is its to invent, a fact is not.

How the search works

There is no vector database and no agent framework here — retrieval is about a hundred lines of ordinary code. BM25 is the classic keyword-relevance formula (the one search engines used before embeddings) run over everything the system has already ingested. It's cheap and it's fast, but it's blind to meaning: search for “prison overcrowding” and it will happily rank “the overcrowding of the prison of self-regard” above a sentencing report, because that headline contains both words.

So a second, tiny model pass reranks the candidates by topical usefulness. It is allowed to reorder what search found and nothing else — it can't add a source, so it can never introduce a citation the brief would then fail to verify. If it errors or answers badly, the keyword order simply stands.

Rerank prompt verbatim, abbreviated
You are ranking retrieved headlines by how useful each one is for
researching a specific topic.

<topic>game licence revoked after purchase</topic>
<candidates>
1. reddit | They revoked my licence to a game I bought in 2019
2. news   | Storefront delistings and what buyers actually own
3. reddit | The overcrowding of my Steam library
...
</candidates>

Judge topical relevance, not word overlap. A headline that shares
words with the topic but discusses something else is NOT relevant —
that is exactly the mistake the keyword ranking already made, and
the reason you are being asked.

Output JSON only, as: {"ranked_positions": [3, 1, 7]}

The two tools the researcher can call

search_discourse(query, limit)

Keyword search over everything already ingested. Returns ids, titles, sources, dates — never full text.

read_source(signal_id)

The full text behind one result. Two or three reads is plenty; it's writing a brief, not a report.

→ read_source("sig_2b07")   the original thread
← brief

Why this one stage uses two different providers

Research is the only stage limited by how much it can read at once rather than how well it can think. On the primary provider the whole growing conversation has to fit inside a 7,200-token per-request ceiling, which means throwing away articles the model already went and fetched. Gemini's intake is large enough that nothing has to be dropped, so it gets the first attempt — capped at four tool turns, because the free tier allows five requests a minute and a full loop is six. That exact overrun cost a render on 1 Sep.

SOFT Any failure at all — a 500, a timeout, malformed JSON, four turns that never stop — falls straight back to Groq. And if research fails entirely, the script is written from the headline alone and the export is stamped ungrounded. A failed brief costs the video its grounding; it never costs the day's video.
04 Script
openai/gpt-oss-120bJSON outno structure gate

Write a person talking, not narration

The writer gets three things and nothing else: the signal, the research brief, and a performance. It returns a hook, a list of beats, and a closing question — as structured data, so every later stage can reason about the parts.

The performance is rolled with dice, not asked for

Told to “vary the tone”, a model varies it across the small space that it finds natural — nine renders came out as the same measured explainer with the same three commas. So the format, the tone at each phase, which non-verbal sounds are in play, roughly how many, and the comedic device are all rolled outside the model from a seed, and handed over as an instruction. Seeded, so the audit package can reproduce it exactly.

Rolled performance seed → prompt block
format   hot_take — a position argued fast and hard that concedes
           exactly once, and is more convincing for it
opening  [incredulous] · [very fast]
middle   [conspiratorial]
closing  [wistful] · [very slow]
sounds   [laughs] [scoffs] [sharp inhale]  — about 4, spread out
comedy   a cliché everyone uses here, said out loud until it
           sounds stupid  — deliver that beat [sarcastically]

Six formats exist — discourse (one mind changing its own position out loud), story, hot take, myth bust, confession, escalation. What is never rolled is the energy shape: hook hard, warm through the middle, soften at the close, on every single video. That's a retention strategy, not a taste.

Delivery tags, and why they can't leak

Beats carry bracketed direction inline — [giggles], [sarcastically], [very slow] — placed where a real person would actually make the sound. The voice model performs them. Everything else in the system gets the text with the tags stripped: the spoken narration on the fallback voice, the stored script, the alignment step, and above all the captions burned into the picture, which cannot be taken back. The guarantee is subtractive, so an invented tag costs a delivery note rather than printing “whispering conspiratorially” across the screen.

GATE There is no structural gate. Scripts used to be failed outright for not being an argument — a story doesn't push back, an escalation has nothing to be wrong about — and that threw away finished renders. Length is advice now: one rewrite quoting the word count to aim at, then the closer of the two drafts ships either way.
05 Critic
openai/gpt-oss-20bdifferent model on purposeadvisory only

A second opinion that never blocks

A separate model reads the finished script cold — it never sees the prompt that wrote it — and scores one thing: did this take a genuine angle, or does it just recite the story back with narrator filler? It also flags anything shaped like defamation of a named real person, medical or legal claims stated as fact, or text that reads as a verbatim repost.

It deliberately runs on a different model from the writer. A critic sharing the writer's model is grading its own work — that was a known compromise for a while, and it isn't one any more.

Critic output
{ "originality_score": 0.72,
  "policy_flags": [],
  "verdict": "approved",
  "reason": "Takes a position and concedes once; not a recap." }
SOFTThe verdict stops nothing. A low score, a flag, or a critic that can't be reached at all — the render continues and the result travels to the reviewer. The score is left empty rather than defaulted, because a placeholder number would read like a real verdict.
06 Plan

Decide what the audience sees

The model is cast as the cinematographer: it can't change a word of the argument, only choose what's on screen while it's made. For each beat it writes a search query and picks a provider — stock library, or real recorded video.

Why spend a model here at all? The first version of this used word-frequency counting and searched for “maybe”, “yet” and “perhaps” — and got a crystal mobile, a ferry railing and two strangers on a hill for a video about moral collapse. “Which phrase in this beat is a picture” isn't a counting problem. This is the one footage decision with real ambiguity, so it's the one that spends a token.

Prompt, the part that matters verbatim
`query` is what gets typed into a stock video search box.
It must name something a camera can point at.

  GOOD: "empty courtroom gallery", "hands sorting paperwork",
        "prison corridor at night", "crowd crossing a wide street"
  BAD:  "maybe", "perhaps", "yet", "morality", "justice", "the truth"

Two to five words. Physical nouns. No proper nouns unless the
script is literally about that place, person or object.

An animated host is composited near the bottom of the frame and
captions sit across the middle. A shot whose entire subject sits
down there is a shot nobody will see.

Bad shots are dropped, never repaired — a query invented to patch a hole is exactly the filler this stage exists to prevent. SKIPThe viral topic never reaches the model. Its background is always gameplay footage cut from random high-motion windows — once the topic has decided the footage, there is nothing left to decide, so it spends nothing.
07 Source
plain code · no modelPexels APIyt-dlpmotion scoring

Go and get the footage

The plan gets executed. Stock answers “an ordinary scene, shot well” — the returned clip is the shot. Real video answers “the actual thing”, and a real video is an hour long with one usable minute in it, so the window is chosen by measuring motion across the file rather than taking the front — which is where a channel puts its intro.

One shot, resolved
shot 3 · query "empty server rack room" · provider pexels
  → clip 8842019 · 14.2s · 3840x2160 · CC0

shot 2 · query "storefront terms page" · provider youtube
  → candidate 47m18s · motion-scored in 5s windows
  → best window 21:04–21:12 · cut · source retained 24h, clip 0h

Downloading a real video is potentially a gigabyte over the operator's own connection, so there's a hard cap per render: four on politics, tech, science and AI — where the real recorded event exists and stock has no clip of it — and two on everything else. Shots past the cap fall back to stock and say so in the audit package.

KEEP Nothing is retained. Clip bytes live in the render's working directory and die with it. What survives is the provenance — provider, source video, the exact seconds used, the query that found it — written before the clip ever reaches the encoder, and deleted when the export retires.
08 Edit
openai/gpt-oss-120bKinocut over MCP9 of 196 toolsfails soft ×2

Find the moment in each clip worth showing

Each clip goes to the model one at a time, along with what that shot is doing in the argument and exactly how long it will be on screen. The model probes it, detects its scene changes, trims to the window that's actually worth the seconds, and optionally applies one subtle grade.

What MCP is, in one paragraph

A model can't edit video by writing text — it has to call something. MCP (Model Context Protocol) is a small standard for exposing real programs as callable functions with described inputs. Kinocut is one such program: an open-source, local-only wrapper around FFmpeg that needs no key and no account. The client that talks to it here is about 150 lines of newline-delimited JSON-RPC over a pipe rather than the official SDK, because three methods over one transport against one server doesn't justify a dependency.

Why only nine tools

Kinocut exposes 196 tools. A tool-calling loop re-sends every tool's description on every single turn, so offering all of them would spend a large share of the day's entire token budget on the menu, before the model looked at one frame. The shortlist is exactly what this stage is for — and the tool descriptions are fetched live from the server at run time rather than copied into the code, because a pasted description silently drifts on the server's next release.

The nine tools · and one clip's real loop
offered: video_info · video_detect_scenes · video_trim ·
video_filter · effect_vignette · effect_glow ·
effect_chromatic_aberration · effect_scanlines · effect_noise

clip 2 — "storefront terms page", 8.0s on screen, intent:
"the words nobody read"
→ video_info(path)              ← 8.4s · 1920x1080 · 30fps
→ video_detect_scenes(path)     ← cuts at 0.0, 2.6, 5.1
→ video_trim(start=2.6, end=8.4) ← the sustained shot
→ effect_vignette(0.25)         ← pulls the eye to centre
← edited · 4 tools · output path verified to exist

Two safety details worth naming: the allowlist is enforced on the call, not merely by what was offered; and the file path the model claims to have written is checked to exist before the encoder is told to read it, because a hallucinated path would otherwise fail the whole render minutes later at encode time.

SOFT Edit is never allowed to fail a render, at either level. One clip whose edit fails keeps its original bytes and stays in the montage. A stage that can't start at all — Kinocut missing, model rate-limited — returns every clip as sourced. Either way the video is exactly the one it would have been before this stage existed, and the reason is written into the audit package. It also does not stitch, composite or encode: those stay in the verified FFmpeg path.
09 Narrate
Edge TTS · defaultGemini TTS · upgradeword timingsWhisper align

Say it out loud, and know when every word lands

The captions in this product are word-by-word — each word accents as it's spoken — which means the system needs the exact millisecond of every word, not just an audio file.

Edge TTS — the default

Microsoft's free voice engine, driven through a thin Python wrapper that explicitly asks for word-boundary events. It returns audio and one {word, start, end} entry per word, so caption timing is exact and costs nothing extra. Voice, rate and pitch are drawn per render from the operator's pool, avoiding voices already used today.

Gemini TTS — the upgrade

More expressive, and the only voice that performs the [giggles]-style delivery tags. Limited to 10 requests per day, so it's one request for the whole video and it's offered only while fewer than 8 of today's renders have used it — two held back so a re-run gets the same voice.

Gemini returns audio and no timings — the single most important technical fact in this design, because switching voice naively would silently delete the caption feature. So when it's used, a Whisper transcription pass force-aligns the audio at word granularity and maps the known beat texts onto the result. Below a 60% word match the alignment is rejected outright, since bad alignment doesn't look like an error downstream — it looks like a video whose captions drift and whose cuts land mid-word.

Three possible caption states always recorded
native     Edge's own word events — exact, no extra call
aligned    Whisper force-alignment — accurate to the match ratio
estimated  alignment failed; words spread across the measured
           duration by length. Flagged in the export, because a
           reviewer can't tell drift from a bad take unless told.
SOFTA Gemini failure falls back to Edge and the render continues, with the reason written down. Edge failing is a real failure — there is nothing below it.
10 Render
FFmpeg1080×1920ASS captionsno model

Cut it to the argument, burn in the words

Every clip is cropped and scaled to vertical and filled to at least three-quarters of the frame height, then joined into one track. Normalising first isn't optional — joining requires the inputs to agree on size, pixel format, frame rate and aspect, and clips from different photographers agree on none of them.

The cuts land on the argument, not on a timer. A shot acquired for beat 3 starts on the first word of beat 3 and holds until the next shot's beat begins. A shot that would run under 900 ms is dropped and its neighbour holds through it, so every millisecond of the video is covered by exactly one shot.

Cut sheet derived from word timings
0.00 – 3.12   hook      "hands holding game disc"
3.12 – 11.40  beat 0    "cursor clicking buy"
11.40 – 19.05 beat 1    "storefront terms page"  (edited: trim+vignette)
19.05 – 27.80 beat 2    "empty server rack room"
27.80 – 36.20 beat 3    "rights document signing"
36.20 – 44.90 beat 4    "empty living room tv"
output length set explicitly from the measured narration

Source audio is muted entirely and the narration mixed in. Captions are burned in as a subtitle track with one event per word, so the spoken word accents as it lands, and keyword words stay accented for the whole line. The host is not in this pass at all — what comes out here is already a complete, publishable Short.

11 Host
FFmpeg · second passno model decides anything19 actionsfails soft

Put the presenter on top

A 19-clip animated character pack is composited over the finished video in its own pass. The performance is fixed: it waves hello, runs the pack's other seventeen actions once through in order, loops that 50.5-second cycle for as long as the video lasts, and waves goodbye. The only rule is that the first and last actions are the waves.

A model used to pick an action per shot from the pack's descriptions, and other code then had to re-check those picks and correct a mid-video sign-off or an invented id. That bought gestures that tracked the argument, and cost a model call whose output needed validating plus a class of bug you could only find by watching. A fixed cycle cannot be wrong and costs nothing.

The cycle manifest order
wave_hello_intro 3.0s → talk_neutral → talk_emphatic →
talk_hand_raised → talk_both_hands_explain → talk_point_right →
talk_point_left → present_open_palm_right → point_up_key_point →
thinking_hand_on_chin → idle_neutral → listening_attentive →
nod_yes_agree → shake_head_no_disagree → thumbs_up_approve →
shrug_uncertain → surprised_reaction → laugh_happy
  ↻ loop the 50.5s cycle …  → wave_goodbye_outro 3.0s

Three engineering details that make it clean: the clips carry a real transparency channel, so there's no colour-keying anywhere (an earlier host was keyed off a red background and the tolerance window ate her face). All nineteen files share one format, so they're joined as a single input rather than forty-odd concurrent decodes. And the track is built to run slightly past the end — an overshoot clips the goodbye wave's tail, an undershoot would leave the last moment with no presenter, which reads as a crash.

SOFTA missing pack or a failed overlay costs the host, not the video. The export is the finished no-host Short, flagged with the reason. Swapping the presenter is repointing one directory — no code knows it's a robot.

Models

Who answers what, and why it's them.

Exactly one file in the codebase is allowed to name a model. That isn't a style rule — a stage that spelled its own model id inline silently missed every model change for weeks, and another shipped a placeholder no provider would accept, which every test passed.

StageModelWhy this one
Research · first trygemini-3.7-flashThe only stage limited by how much it can read at once. Big enough intake that no fetched article has to be thrown away. Capped at four tool turns against a 5-per-minute ceiling.
Research · fallbackopenai/gpt-oss-120bFires on any failure — 500, 429, timeout, bad JSON, a loop that won't stop. Known to work; no ladder to a third model, because handing a second model the first's signed reasoning steps is untested.

Everything else—Watch, Score, Source, Render, Host, Ideas ranking and the whole audit package are plain code. The web service makes no model call anywhere.

The budget is the design constraint

Tokens are metered per model per day, so every stage sharing a model competes for one allowance. What's on the big model costs about 130K tokens a render, which makes two renders a day the practical ceiling — and Edit is nearly all of it. The fix, when it's needed, is fewer tool turns or a shorter tool list, not a smaller model.

Adding a provider requires a human decision

Research is the one stage with two providers, and it is explicitly not a precedent for a third or for a second stage. No framework, service or model provider enters this system without the operator saying so — which is why there's no vector database, no agent framework, and a 150-line MCP client instead of an SDK.

The output

What lands on the operator's desk.

A finished vertical MP4, a listing to paste, and everything needed to check the video is what it claims to be. It sits in the review queue for three days; downloading it, marking it reviewed, or throwing it away are all one click.

A real export from this pipeline — footage, narration, word-level captions and the host, exactly as the system produced it.

Every package contains

  • ✓The video. 1080×1920 MP4, narrated, captioned, hosted, ready to upload as-is.
  • ✓The upload sheet. Title, description and hashtags, written for the platform rather than cut off mid-word.
  • ✓The script as written, plus the performance it was rolled and the seed that produced it — so the same run can be reproduced from the package alone.
  • ✓The critic's verdict, or an honest empty where the critic couldn't be reached.
  • ✓The research brief and its citations — or a clear ungrounded stamp when the script was written from the headline alone.
  • ✓Footage provenance for every clip: where it came from, a link that opens the source at the right second, the span of the source used, and the span of the finished video it occupies.
  • ✓What the edit did to each clip, or why it was left alone.
  • ✓The voice settings actually used — driver, voice, rate, delivery direction, and which of the three caption-timing states produced the words on screen.
  • ✓Which provider answered each thinking stage, and why the other one didn't.
  • ✓Flags: length misses, a caption drift, a repeated-sounding script, a voice reused today, a missing host, a degraded stage. None of them block; all of them are told.

Non-negotiables

Rules the system is built not to break.

Almost every one of these exists because something went wrong once and the fix was written into the architecture rather than into a habit.

It never uploads.No upload credential, no OAuth scope, no publish endpoint, anywhere in the system. Publishing is a person in YouTube Studio.
It never hands over a video without its receipts.Script, critic, research, footage provenance, voice settings, model per stage, host sequence. An export missing them is useless to a reviewer, so it can't be produced.
It never keeps footage.Clip bytes die with the render's working directory. Provenance rows are dropped when the export retires. The only exception is a 24-hour cache of long source videos, so a repeated run doesn't re-download 1.6 GB.
A helper stage never kills a render.Research, Plan, Edit, alignment, the critic and the host all degrade and report. The video that comes out is the one that would have come out before that stage existed.
A delivery tag never reaches the picture.Bracketed direction goes to the expressive voice model and nothing else — never the fallback voice, never the stored script, and never the burned-in captions, which can't be taken back.
No secret is ever written down.Not in a file, a log line, a commit message or a client bundle. Keys arrive from the environment and live in an encrypted vault only the drivers can open.
A run makes the plan just submitted, or nothing.It claims stories from that plan alone. A run whose plan is empty makes no video rather than falling back — no token is spent on a story chosen in an earlier session.
A failed run's story is cancelled, not retried.Re-choosing takes one click. Silently re-rendering a thirteen-hour-old story in a run sized for one video does not.
The model is spent only where there's real ambiguity.Footage acquisition, the host's performance, the ideas ranking and the whole audit package were all agentic once. Each became plain code the moment it was shown to have one right answer.
