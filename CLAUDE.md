## Role

You are the on-call engineer for an autonomous video publishing system. It runs unattended around the clock and uploads to a real YouTube channel under a real person's name. You will be paged when it breaks. Write the code you want to be woken up by.

## What this is

A single-operator platform that monitors trending, polarizing discourse across Reddit, X, news RSS, and YouTube, synthesizes a 130–170 word provocative narrative script around it, pairs the narration with a heavily-transformed clip from a maintained library of long-form gameplay walkthroughs, burns in word-level animated captions, and renders three YouTube Shorts a day as downloadable packages — video, script, rationale, and full provenance — for the operator to manually review and upload. The operator steers it from a passkey-protected surface — one page, **two routes behind a fork** (operator direction 2026-09-04). **Brainstorm first** is the original six visual stages, described in `docs/SIX_STAGES.md`: choose how many videos a run makes, each one's topic, and each one's story, ranked out of the discourse WATCH has ingested. **Already have an idea** is the chat route, described in `docs/CHAT_PIPELINE.md`: one prompt plus files, digested and grounded on the runner, and then the *same* SCRIPT→EXPORT chain. Voice, speed, source and game preferences live in the directive the pipeline reads; a chat brief may override voice and language for its own render only. The system's two hard constraints: it never hands the operator a video without full audit context (script, critic output, footage provenance, TTS settings actually used — see §9 of `ARCHITECTURE.md`), and it never uses footage outside the maintained, provenance-tracked library.

The whole product is that surface — the landing, the fork behind it, and the two routes behind that (`src/app/state.ts`'s `STAGES`; the routes share `review` and nothing else). The old multi-page console (`/console/*`, dashboard, chat, voice, settings) was deleted on 2026-08-31 by operator direction, and with it the "one React island, everything else plain Astro + vanilla TS" rule; React was already a dependency, so no framework was added. The glass in `src/app/glass/**` is the 21st.dev component "Broken by Design" by @gughigug, used with its exact assets (vendored to `public/shards/`) — see that directory's file headers.
- **One Cloudflare Worker with static assets** — serves the app and the API. **Not Pages.**
- **D1** (Drizzle) for state, **KV** for hot JSON and the encrypted key vault
- **Every reasoning stage is a model ladder** (operator direction 2026-09-04), named once in `src/config/models.ts` and assembled in `src/lib/drivers/resolve-ladder.ts`. A stage no longer names one model; it names an ordered list and takes the first rung that answers. `LadderLlmDriver` (`src/lib/drivers/llm-ladder.ts`) is the mechanism and it is deliberately dumb: try, and on **any** driver error — a 500, a 429, a timeout, a malformed body — step down to the next rung. There are three ladders and no others. **The general ladder is `gemini-3.5-flash-lite` → `openai/gpt-oss-120b` → `openai/gpt-oss-20b`**, and it answers SCRIPT, PLAN, retrieval **reranking** (`src/lib/rag/rerank.ts`) and RESEARCH's post-Gemini fallback. **EDIT's is `qwen/qwen3.8-27b` → `qwen/qwen3.6-27b`**, Groq both rungs. **CRITIC and EXPORT's title/description/hashtag listing are `openai/gpt-oss-20b` outright**, no ladder (operator direction 2026-09-03) — both are advisory or already fail soft to a heuristic, and moving CRITIC also ended the compromise where the critic ran on the writer's own model. **The descent is sticky**: once a rung fails inside a stage, that stage does not climb back to it — a 429 is a statement about the next minute, and re-offering the rung that just refused spends a request to learn the same thing twice. Each stage gets its **own ladder instance** (so a rate-limited rerank does not decide where SCRIPT starts) over **one shared set of drivers** (so three stages do not each believe they hold the whole 5 requests/minute). Which rung actually answered reaches the audit package per stage, read off `lastUsed()` — never written down by hand. This is not the 2026-09-01 arrangement returning: that one made Gemini a *dependency* behind a fallback that fired only on quota exhaustion, so two 500s went straight through it and killed the render at SCRIPT; a stage can only fail now if every rung fails. **Gemini also buys narration and RESEARCH's first attempt** (operator direction 2026-09-01 and 2026-09-02). RESEARCH goes to `gemini-3.8-flash` for **at most four tool-loop turns** and, on *any* failure, starts over on the **general ladder from its top rung** — `gemini-3.5-flash-lite`, then `openai/gpt-oss-120b`, then `openai/gpt-oss-20b` (operator direction 2026-09-04, `src/lib/rag/research-provider.ts`); it is the one stage bounded by intake rather than reasoning, because Groq's 7,200-token per-request ceiling makes `fitToRequestBudget` discard sources the model already fetched, and Gemini's does not. Four is not arbitrary: the free tier meters **5 requests/minute per text model**, RESEARCH's full loop is six, and the first live run of the 2026-09-01 split peaked at 6/5 and lost the render at SCRIPT. `GEMINI_REASONING_MODEL` is a *different model id* from RESEARCH's for exactly that reason — the meter is per model, so RESEARCH's first attempt and the general ladder never share a bucket. RESEARCH's *fallback* is the general ladder itself, Gemini rung included, and that is not the second-Gemini-attempt rule reversed: that rule is about a second model inside **one transcript**, and the fallback abandons the first attempt whole and starts a new loop from an empty one, on a different model id and so a different bucket. The ladder instance is the render's own, so the rung is the same driver and the same limiter SCRIPT, PLAN and reranking hold. Three things from that failure stay fixed: the fallback fires on **any** error, the Gemini drivers take **no HTTP retries** (`maxAttempts: 1` — "once"), and there is **no ladder between two Gemini models inside one tool loop**, because handing a second model the first's signed `thought` steps is untested and would fail only in production. `LlmMessage.providerSteps` is back for the same reason it existed: Gemini cannot replay a tool conversation statelessly. **What this does to the budget:** Groq meters tokens per model per day, and EDIT — ~90-110K tokens a render across ~34 tool turns — was almost all of the ~130K that made two renders a day the ceiling. The qwen3 models carry a **2M/day** allowance, so the largest consumer has left the 200K bucket that binds, and `EDIT_TOOLS` is three tools rather than nine (~2.1K tokens of re-sent schema per turn, cut by roughly two thirds). **The Worker makes no model call anywhere.** The in-console chat and voice agents went with the console on 2026-08-31; stage 4's rerank was the one exception for a single day and was deleted 2026-09-03 by operator direction, taking `RouterEnv.GROQ_API_KEY` with it. The Worker needs no model credential at all. Footage acquisition used to run a browser agent here (on `qwen/qwen3.8-27b`); it was deleted on 2026-08-29 once the converter flow was shown to be deterministic, so FOOTAGE REFRESH now spends no tokens at all
- **The chat route is a prelude, not a second pipeline** (operator direction 2026-09-04, `docs/CHAT_PIPELINE.md`). `scripts/pipeline/chat-render.ts` digests the operator's typed brief, grounds it, manufactures exactly the state `renderOneVideo` already expects — a `signals` row in state `scored` (`src/lib/pipeline/brief-signal.ts`, migration 0017 widened `sources.kind` to admit `operator`) plus a run plan naming it — and then calls that function. SCRIPT through EXPORT are byte-for-byte the brainstorm route's, because RESEARCH's entire contract with everything downstream is one nullable `ResearchBrief`, so *supplying* it is indistinguishable from producing it. **DIGEST is stage 0** (`src/lib/pipeline/digest.ts`) and runs in Actions on the general ladder — never in the Worker, which still holds no model credential; the chat surface watches the run rather than waiting on a reply, which is what the design board draws. **A vague prompt falls back deterministically**: `isBareTopic` is plain code (two content words or fewer, after stopwords, or an empty angle) and overrides the model in one direction only, then `rankIdeas(topic, 1)[0]` — stage 4's own function, no model in the selection — supplies the story. The operator never leaves the chat surface. `POST /console/briefs` is the one write, multipart, capped at 5 files and 20 MB, bytes into R2 under `briefs/<id>/<n>` and back out to the runner through `GET /internal/briefs/:id/:n` behind the existing `PIPELINE_BATCH_TOKEN` — no new credential anywhere

BM25 over `signals` is *wrong* on this route rather than merely unavailable: a chat brief may be about something an hour old that no feed here carries, so retrieval would return something adjacent, and a script grounded in something adjacent is worse than an honest ungrounded one. The bounds are RESEARCH's own — four turns, `maxRetries: 0`, `GEMINI_RESEARCH_TIMEOUT_MS` as an `AbortSignal` — and the trust boundary is the same shape as `finalizeBrief`'s: a claim survives only if its URL is in the provider's grounding metadata. Those citations carry `signalId: null` and `sourceKind: "web"`, and the audit package reports the stage as `gemini-grounded`, because a corpus citation can be looked up here and a web one has to be opened
- **Kore and English are the defaults on both routes** (operator direction 2026-09-04, `src/lib/pipeline/narration-voice.ts`). A chat brief may override either, for its own render only, never touching the directive. The two knobs are asymmetric and that is the provider's fact: Gemini TTS takes a voice as a request field and has **no language field at all**, so a language reaches it as prose in the style direction; Edge encodes the locale *in* the voice name and its pool is eight English voices, so anything else is an **unmet request that is reported** rather than silently narrated in English. Expressive delivery is untouched — `rollPerformance` still seeds laughter into every `nonVerbal`, and `stripTags` still keeps a tag out of `scripts.body`, ALIGN and the captions
- **The gradient orb is the 21st.dev component, vendored verbatim** (`src/app/orb/GradientOrb.tsx`, operator direction 2026-09-04 — "use DIRECTLY THE EXACT one"). It replaces both the design board's black hole and its aurora. It is the only thing here that pulls in `three` and `@react-three/fiber` — ~238 KB gzipped against the app's own 110 KB budget — so it is reached **only** through `OrbLazy.tsx`, `astro.config.mjs` gives it a chunk of its own, and `package.json` holds two size budgets that mean different things: the app's, which must not grow, and the orb's, which is what it is. The landing, the passkey ceremony and the whole brainstorm route download none of it
- **Microsoft Edge TTS** (unofficial, free, no key — see `ARCHITECTURE.md` §3), via the `edge_tts` Python library shelled out to from `src/lib/drivers/tts-edge.ts`, for narration + word-level caption timing. **Gemini TTS's timeout is derived from the text, not a constant** (`timeoutForText`): synthesis is superlinear in length — 48 words measured at 19.8s, 234 at 245.1s — and the flat 120s that stood until 2026-09-02 was *below the measured cost of an ordinary script*, so every full-length Gemini narration timed out, retried, timed out again and landed on Edge four minutes later. The retry went with it (`maxAttempts: 1`): the daily ledger records once per `synthesize()`, so a driver sending two requests per call under-reports spend against a ten-a-day quota
- **The Ideas stage is BM25 and is current at the moment it is opened** (operator direction 2026-09-03, `src/server/console/ideas-refresh.ts` + `src/server/console/ideas.ts`). No model orders this list: a reranker sat here for one day and reordered the same corpus into nearly the same order every visit. Freshness is two pieces of plain code instead. **(a) `POST /console/ideas/refresh` re-runs WATCH's ingest and SCORE once per entry, polling one source per host, rotating by `lastSeenAt`, with `retryOn429` off.** Measured 2026-09-03: reddit.com serves roughly **one RSS request per IP per 30-60 seconds** — three concurrent requests came back 429/429/429, a single one came back 200 with 25 entries, and a second five seconds later came back 429. The old refresh fired all five sources concurrently with three retries each, so up to nine reddit.com requests in one burst, so every Reddit fetch on entry failed. Adding subreddits to `data/sources.yml` lengthens the rotation; it does not add requests. **(b) `rankIdeas` carries a recency weight** (0.25, exponential, 12-hour half-life, deliberately un-normalized). Without it the blend said nothing about time at all, so a week-old story outranked one ingested seconds ago whenever it had marginally better term overlap — over a candidate pool several days deep. The feeds are `rising.rss`, not `hot.rss`: a `hot` feed's newest entry measured ~4 hours old. Neither half may fail the screen. And `seedSourcesFromYaml` now reconciles `url`/`enabled` on existing rows — it only ever inserted before, so an edited feed URL never reached a seeded database
- **FFmpeg + Python 3** (for `edge_tts`), run in **GitHub Actions** (Cloudflare Workers cannot run FFmpeg or spawn subprocesses — no native binary execution, hard CPU-time ceiling) for the per-render video pipeline
- **Retrieval is plain code, not a framework** (ARCHITECTURE.md §5.2.5): BM25 over the `signals` corpus (`src/lib/rag/bm25.ts`), wrapped as tool-call functions, with the model **reranking** the candidates BM25 returns (`src/lib/rag/rerank.ts` — it may only reorder what retrieval found, never add to it). That reranking is RESEARCH's, inside the pipeline, and the only one left: stage 4's was deleted 2026-09-03. No CrewAI/LangGraph/vector DB; the `EmbedDriver`/`VectorDriver` stubs stay stubs until there is a recall eval set to justify one. `Retriever` is the seam if that changes, and `RerankingRetriever` is what it looks like when used
- **Video editing is Kinocut over MCP** (`src/lib/pipeline/edit.ts`, added 2026-09-01 by operator direction): the EDIT stage runs between SOURCE and RENDER and has the model find each clip's key moment, trim to it, and grade it. Kinocut is local-first and Apache-2.0 (no key, no account, wraps FFmpeg); the MCP client is ~150 lines of newline-delimited JSON-RPC in `src/lib/drivers/mcp-stdio.ts` rather than the MCP SDK, for the same reason retrieval is not a framework. **EDIT does not stitch, composite or encode** — `render-ffmpeg.ts` still does, and EDIT fails soft to "every clip as sourced" at both the per-clip and whole-stage level. **Exactly 3 of Kinocut's 196 tools are ever offered** — `video_info`, `video_detect_scenes`, `video_trim` (operator direction 2026-09-04, down from 9) — because every offered schema is re-sent on every turn of every clip, and the six grading tools were two thirds of that menu. The consequence is stated rather than hidden: EDIT no longer grades or stylises, and nothing downstream picks that up
- **Footage is planned, sourced per render, and retained by nothing** (operator direction 2026-09-01, `docs/SIX_STAGES.md`). PLAN (`src/lib/pipeline/shot-plan.ts`) turns the script into an ordered shot list — one shot per beat, each with a *filmable* query and a provider — and SOURCE (`src/lib/footage/source-agent.ts`) executes it against Pexels and YouTube, motion-scoring a long YouTube source to find the window worth showing. The `viral` topic short-circuits PLAN entirely: its background is always a GTA 6 walkthrough, cut from random top-motion windows after a head/tail buffer. **Sourcing is open** — any YouTube channel, not just the maintained one (migration 0008 no longer binds this path; the weekly FOOTAGE REFRESH is unchanged). **The YouTube download cap is topic-aware** (operator direction 2026-09-01): 4 for `politics`/`tech`/`science`/`ai`, where the real recorded event exists and stock has no clip of it, and 2 for everything else. PLAN is told to prefer `youtube` on those four topics. Shots past the cap fall back to stock and say so. **SOURCE downloads with `yt-dlp`** (`download-ytdlp.ts` — the converter route is FOOTAGE REFRESH's, not this one), so a runner without that binary silently makes an all-stock video: every `youtube` shot fails `spawn yt-dlp ENOENT` and falls back, and a `viral` run — which is gameplay or nothing — fails outright at SOURCE. Both happened on 2026-09-02; `render.yml` now installs it and warns loudly when it cannot
- **Browser-driven footage acquisition** (ARCHITECTURE.md §5.0): the weekly footage-refresh job drives a real headless Chromium (Playwright), and **both legs are deterministic — zero model calls, zero tokens**. One enabled channel, @HollowPoiint, pulled at 1080p; every source is head/tail-trimmed by 10 minutes on arrival and clipped into 65s segments drawn at random from the top motion-scored windows. Search (`youtube-search-dom.ts`) reads youtube.com's results for `"<game>" walkthrough "<channel>" youtube` straight off the page; convert+download (`download-ytmp3-dom.ts`) drives `https://media.ytmp3.gg/tools/youtube-to-mp4-converter/dbismy` by its ids and **waits on the page's own state machine** (`.status` → `#download-btn[data-url]` | `.status--error`), never a fixed sleep. The agentic version of that leg was deleted 2026-08-29: the page has one right answer at every step, so there was nothing for a model to decide. Spend the model where there is real ambiguity, nowhere else. Replaces yt-dlp and the YouTube Data API v3 search — both removed. No upload/OAuth scope exists anywhere in this system — publishing is manual, done by the operator in YouTube Studio
- **EXPORT writes a real listing** (`src/lib/pipeline/upload-metadata.ts`): one Groq call for the title, description and hashtags the operator pastes into YouTube Studio, failing soft to a listing derived from the script. ARCHITECTURE.md §5.9 has claimed this since it was written and RENDER was passing `script.hook.slice(0, 100)`, `script.body.slice(0, 500)` and `suggestedTags: []` — every export ever made carried a description cut off mid-word and no tags at all, which nothing noticed because nothing rendered them until stage 6's Metadata sheet
- **GitHub Actions** as the pipeline runner and scheduler for everything compute-heavy; a Git orphan branch (`assets-library`) as the footage clip store. **R2** holds rendered export blobs (bucket `mythosengine-exports`), added 2026-08-31 by operator direction: KV caps one value at 25 MiB and a 128s 1080x1920 render is 42–60 MB, so EXPORT could not complete at all. The pipeline never touches R2 directly — it writes through the Worker's binding via `PUT /internal/exports/:key`, so no new credential exists
- **Every video is rolled a performance, and the script is written to it** (operator direction 2026-09-03, `src/lib/pipeline/performance.ts`). `rollPerformance(traceId)` picks the format (`discourse · story · hot_take · myth_bust · confession · escalation`), the tone and pace at each phase of the arc, which non-verbal sounds are in play and roughly how many, and the comedic device — seeded, so it is reproducible from the audit package. **The energy shape is not rolled**: hook hard, warm through the middle, soften at the close, on every video. Scripts carry Gemini's **inline delivery tags** (`[giggles]`, `[sarcastically]`, `[very slow]`) inside the beat text, and `src/lib/pipeline/delivery-tags.ts` is what keeps that safe: Gemini gets the tags, and `stripTags` removes them on the way out to Edge TTS, `scripts.body`, ALIGN and the burned-in captions. The guarantee is subtractive — an invented tag costs a delivery note, never a caption reading "whispering conspiratorially". **There is no structure gate**: the rule that a script had to be a discourse (a `pushback` between an `attempt` and a `land`) failed whole renders for scripts that were merely a different shape, and was removed with it. Length is a guide — one rewrite, then the closer draft ships either way
- **The host is a 19-action character pack on a fixed cycle, composited by its own pass** (`assets/character/robot_character_pack/`, operator direction 2026-09-03). **No model decides anything about it.** It waves hello, runs the pack's other 17 actions once through in manifest order, loops that 50.5s cycle for as long as the video lasts, and waves goodbye — the only rule being that the first and last actions are the waves (`src/lib/pipeline/character-timeline.ts`, pure, no I/O). PLAN no longer chooses actions and nothing validates or corrects them, because a fixed cycle cannot be wrong. **RENDER produces a finished, publishable Short with no host in it** — footage, narration, burned-in captions — and `src/lib/drivers/character-overlay-ffmpeg.ts` composites the host on top of that in a second ffmpeg pass, which is why a failed overlay costs the host and not the video. That pass uses ffmpeg's **concat demuxer** (one input, not ~44 `-i` arguments for a 128s video) and stream-copies the audio; it works because every pack MOV is `png / 640x680 / rgba / 12fps` and PNG is all-intra, so the single `outpoint` trim that lands the wave on the end is frame-exact. The track is built to run *past* the video's end rather than stop short of it — an overshoot clips the wave's tail, an undershoot would leave the last moment hostless. Two accepted consequences: the host cuts on its own cadence rather than the footage's, and the pack's silent actions play under continuous narration. **There are no frame holds and no chroma key anywhere** — the MOVs carry a real 8-bit alpha channel, so the `colorkey` whose tolerance window ate the old host's face is gone. Swapping the presenter is repointing `CHARACTER_PACK_DIR`; no code knows it is a robot

## NEVER

Re-read this block before writing any file that touches secrets, auth, the database, footage, or an external call.

- Never write a secret, API key, OAuth token, or refresh token into a tracked file, a `PUBLIC_*` variable, a log line, a commit message, or a client bundle.
- Never ask me for a secret value. Secrets arrive through the environment. If a command fails for lack of a credential, name the exact variable and where to set it, then stop.
- Never import a package that is not already in `package.json` without first running `npm view <pkg> time.created maintainers` and pasting the output.
- Never use `any`, `as unknown as`, `@ts-ignore`, or `eslint-disable` to make an error go away.
- Never write an empty `catch` block, swallow an error, or return fallback data on failure.
- Never perform a multi-step database mutation outside a transaction.
- Never call drizzle's `.get()` on an `AppDb` — use `getOne()` from `db/client.ts`. Over the D1 HTTP client a `.get()` that matches nothing returns a **truthy** row of `undefined` fields, so every `if (!row)` guard silently stops working. That broke every scheduled RENDER from 2026-08-29 to 2026-08-31.
- Never `.innerJoin()`/`.leftJoin()` on an `AppDb`. Query each table and join in memory. Drizzle emits an unaliased select list, D1's REST response is a column-keyed JSON object, and two tables that both have an `id` collapse into one key — the row comes back a value short and every field after the collision is shifted. Confirmed against the live database, 2026-08-31.
- Never call `fetch` without an `AbortSignal` timeout.
- Never let `vault.get()` be called outside `src/lib/drivers/**`.
- Never give this system a YouTube upload credential, OAuth scope, or refresh token, and never call a YouTube upload endpoint from any component. There is no automated publish path, by design — see §9 of `ARCHITECTURE.md`.
- Never retain sourced footage past the video it was sourced for. Clip bytes live in the render's work directory and die with it; `footage_segments`/`render_footage_parts` rows are dropped when the export retires (`db/exports-reap.ts`); nothing is committed to `assets-library` any more. The single exception is the 24h YouTube *source* cache (`.footage-cache/`, gitignored, swept by age), which exists so a viral run does not re-pull 1.6 GB hourly — no clip and no Pexels byte goes there.
- Never let the operator's review surface hide a fact the audit package already carries. Stage 6's **Metadata** sheet (`GET /console/exports/:id/metadata`) is where the description, the hashtags, the per-clip footage provenance — source link and the span of the source used — and **which clips EDIT cut through Kinocut MCP, on which model** are read. Footage provenance was recorded correctly from the day §9 was written and was on screen nowhere, so "which YouTube videos are in this?" was answerable only from a CI log.
- Never omit the audit package (script, critic output, footage provenance *for every clip in the video*, the RESEARCH brief and its citations, TTS settings actually used, which of the three `captionTiming` states produced the captions, **which provider actually answered each reasoning stage**, **what EDIT did to each clip**, and **which pack the host came from and the sequence it performed**) when exporting a rendered video. An export without it is useless to a human reviewer. A render whose RESEARCH failed is exported flagged `ungrounded`, never exported silently as though it were grounded.
- Never send Groq a request bigger than its per-minute token bucket. The 8,000 TPM ceiling applies **per request** as well as per minute, and a request over it is refused with HTTP 413 before anything runs — the rate limiter cannot help, because it clamps an oversized demand to the bucket and lets it through (by design; see `acquire()`). RESEARCH is the stage that grows, and it bounds itself with `fitToRequestBudget`. Two renders in a row lost their grounding to this on 2026-09-02.
- Never budget a provider's *daily* quota against a UTC day or against rows that only record successes. Gemini's free TTS tier resets at midnight **Pacific** and counts every request, including the ones that fail and the ones a later stage throws away; `src/lib/pipeline/tts-budget.ts` is the only thing that may answer "how much is left today". Counting `renders` rows against a UTC midnight is what silently replaced Kore with `en-US-GuyNeural` on 2026-09-02, and retrying that 429 spent an eleventh request to learn the same thing twice.
- Never add a field to `DirectiveSchema` without `.optional()`. A stored directive was saved by whichever build was running then, so it has no key for any field added since, and `.nullable()` alone rejects a *missing* key — `getSettings` throws a ZodError and every RENDER dies before it reads a signal. Cost one dead run on 2026-09-01.
- Never send a Groq request without a `user` message, and never let one ask for more output tokens than the model's per-minute output ceiling. Both are HTTP 400 `invalid_request_error`, refused in milliseconds with nothing billed, and neither is a 429 the retry path or the rate limiter can do anything about — `acquire()` clamps an oversized demand and lets it through by design. The qwen3 models' chat template raises `"No user query found in messages"` on a system-only conversation, and their **output** meter is **1,000 tokens/minute enforced per request** (`QUOTAS.groq.outputTokensPerMinuteQwen3`, measured 2026-09-04); gpt-oss has neither restriction, which is exactly why EDIT inherited a system-only prompt and `max_tokens: 1024` from it and then refused every turn of every clip on both rungs the day it moved. A prompt shape and a token budget are part of a model's contract and do not travel across a model change for free.
- Never give a JSON-mode Groq call a completion budget that the model's reasoning can fill before it emits. Groq validates JSON mode server-side, so a truncated generation returns HTTP 400 `json_validate_failed` rather than short JSON — and a stage that fails soft turns that into a silent degrade. `METADATA_MAX_TOKENS` was 1,024 against listings measured at 1,571 output tokens, so **every** export EXPORT's listing call was written to produce came back heuristic with a plausible reason. 3,072 is the figure `request-json.ts` already derived for the same reason on 2026-08-31.
- Never let EDIT fail a render. A missing `uvx`, a missing Kinocut, **both rungs of the EDIT ladder rate-limited**, or a clip the tool loop cannot finish means "every clip as sourced", flagged in the audit package — never a thrown error, at either the per-clip or the whole-stage level. The ladder's descent to `qwen/qwen3.6-27b` is sticky for the rest of the stage: the run *continues* on the second model, it does not re-offer the first once per clip. Same contract for RESEARCH: a failed brief costs the render its grounding and is exported flagged `ungrounded`, never the day's video.
- Never add a model or a provider to a reasoning stage without explicit operator instruction, and never let a stage assemble its own ladder. `src/config/models.ts` is the only place that names a model and `src/lib/drivers/resolve-ladder.ts` is the only place rungs are ordered — that is not a style rule: CRITIC spelled `"openai/gpt-oss-120b"` inline from the day it was written and silently missed every model change until 2026-09-03. A stage that names its own model id inline (as EDIT and rerank once did, with a placeholder no provider would accept) fails in production while every test passes. A stage passing a model to `LlmDriver.complete` is passing its default for the case it is handed a plain driver; the ladder overrides it, and that is deliberate.
- Never give a Gemini stage a flat timeout below the measured cost of a real request. `gemini-3.8-flash` answers a RESEARCH-sized turn in 28.8s, 54.4s or 144.9s (measured 2026-09-04, all three HTTP 200), so the driver's 60s default aborted the majority of them mid-answer and RESEARCH's first attempt structurally never landed — the operator's chosen model implemented in name only. `GEMINI_RESEARCH_TIMEOUT_MS` is 180s for that reason, and the four-turn cap is what bounds what it can cost. This is the 2026-09-02 TTS lesson in a second place: a timeout under the real cost does not degrade a path, it deletes it, quietly, while every test passes.
- Never let RESEARCH's Gemini attempt exceed four turns, take an HTTP retry, or descend to another Gemini model **inside its own tool loop**. Four turns is what keeps it under the 5 requests/minute ceiling that lost the 2026-09-01 render; a retry spends a request against a window it cannot outrun; a second Gemini model mid-loop would be handed the first's signed `thought` steps, which is untested and fails only in production. The fallback fires on **any** failure — a 500, a 429, a timeout, bad JSON, a schema miss, or four turns that never stopped calling tools — and since 2026-09-04 it is the general ladder from the top (`createReasoningLadders(...).forStage("RESEARCH")`, operator direction): `gemini-3.5-flash-lite`, then `gpt-oss-120b`, then `gpt-oss-20b`. That is a *new loop from an empty transcript* on a *different model id*, which is the whole distinction — nothing is handed across, and `LadderLlmDriver` still places at most one Gemini rung, at the top, so no single tool conversation ever steps Gemini→Gemini. Take the ladder from the render's shared `ReasoningLadders`, never build one here: three private limiters against one 5-requests-per-minute meter is the arithmetic that lost that render.
- Never offer a model the whole of an MCP server's tool surface, and never grow `EDIT_TOOLS` past the three the operator set on 2026-09-04. Kinocut exposes 196 tools whose schemas are re-sent on every turn of a tool loop; `EDIT_TOOLS` is `video_info`, `video_detect_scenes`, `video_trim`, and the allowlist is enforced on the call, not merely by what was offered. A tenth tool added back costs every turn of every clip its schema and nothing would notice.
- Never give the Worker a model credential, and never put LangChain in the Worker or the client bundle. The chat route did not change this: `POST /console/briefs` stores a prompt, stores its files and starts a run, and every judgement about that brief — its topic, its title, whether it is specific enough to build — is made by DIGEST in GitHub Actions and written back onto the `briefs` row. The cost is a minute of latency on a cold runner, and the design absorbs it: the orb rises on the keypress, so the acknowledgement is the animation. `scripts/check-console-isolation.mjs` enforces the client half.
- Never let the chat route's DIGEST, its attachment reader, or its grounded RESEARCH fail a render. Same contract as RESEARCH, EDIT, CRITIC and the host overlay, at every granularity: a dead DIGEST costs the run its classification and takes the bare-topic branch; an unreadable attachment costs that file's content and one line in the digest prompt; failed grounding costs the brief its grounding and falls to the corpus path, then to `ungrounded`. The only thing that may end a chat run early is having no idea at all to build, and that is `skipped`, not a failure.
- Never let a chat brief reach SCRIPT without a real `signals` row in state `scored`, and never build the chat route a second orchestrator. The FK on `scripts.signal_id`, `claimNextRunPick`'s eligibility subquery, `queuePlan`'s validation and the `scored → scripted` transition all assume that row exists; `src/lib/pipeline/brief-signal.ts` mints it, inserted **directly as `scored`** so SCORE's duplicate clustering never sees it — a brief about a story already in the corpus would otherwise be rejected as a duplicate of the very story the operator is trying to talk about. Queueing a real run plan is what makes PLAN, SOURCE's topic-aware download cap and EXPORT's hashtags need no chat-route special case at all. A second orchestrator would mean two places that know about the Groq token bucket, the Gemini TTS Pacific-day ledger, the sticky ladder descent and the export lifecycle, and the second would drift the first time either changed.
- Never make the chat route's vague-prompt fallback a model decision. `isBareTopic` is plain code and overrides the model in one direction only, and the fallback itself is `rankIdeas(topic, 1)[0]` — stage 4's own function, BM25 plus engagement plus the recency weight, no model in the selection. "Deterministically" was the operator's word: the same corpus and the same topic must give the same story, and the operator must be able to open stage 4 and see why it won.
- Never let a voice or language request be silently unmet. Gemini TTS has no language field and Edge's pool is eight English voices, so some requests genuinely cannot be honoured — `resolveNarrationVoices` returns `unmetRequest`, RENDER logs it, and `narration.voice` keeps recording what actually spoke. An export that says one thing and sounds like another is the 2026-09-02 failure, and it is worse than a request that was refused out loud.
- Never let the orbiting shards be driven through `useShardField`, and never put a second `transform` animation on `.orbit-shard`. That hook's targets are closure-private and are reset by its own pointer handlers; the orbit is a wrapper layer above it, exactly as `ShardPlayer`'s spread is. Three transforms, three owners, no two on one element — and in particular the orbit wrapper must never carry `.float-group`, whose drift keyframe animates the same property.
- Never let the chat route's building screen show progress that did not happen. Six counted facts — digested, story, script, render, encoded, export — each one a row something wrote after doing the thing, never a timer and never an ETA. This is the rule `Stage5Forge`, `ForgePane` and `src/server/console/runs.ts` already state, and the screen the operator stares at for twenty minutes is the worst place to break it.
- Never import `src/app/orb/GradientOrb.tsx` anywhere but `OrbLazy.tsx`, and never fold the orb chunk back into the app's size budget. It is `three` + `@react-three/fiber`, ~238 KB gzipped against an app budget of 110 KB. Two size-limit entries, and the app's one continuing to pass is the standing proof that the chat route did not make the brainstorm route heavier.
- Never call a pipeline entrypoint's `main()` at module scope once anything imports that file. `scripts/pipeline/chat-render.ts` imports `renderOneVideo` from `render.ts`, and an unguarded `main()` there meant *importing* it started a second, unrelated brainstorm render — claiming a queued pick from an earlier session and spending the day's token budget, beside the chat run the operator actually asked for. Caught locally on 2026-09-04, before it ever ran with credentials, by two `main` frames in one stack. The guard is `import.meta.url === pathToFileURL(process.argv[1] ?? "").href`, and `scripts/pipeline/render-entry.test.ts` is what keeps it there.
- Never create a Cloudflare Pages project, rename the Worker, or regenerate an existing secret.
- Never let a render claim a pick outside the plan it was dispatched for, and never requeue a pick whose run failed. `POST /console/dispatch` names the newest queued plan as the workflow's `plan_id`, sizes the run to that plan, and `claimNextRunPick` claims from it alone; an invocation whose plan is empty makes **no video**, rather than falling back to the diversity-weighted signal (operator direction 2026-09-03). A failed or killed run's pick is **cancelled** by the next invocation's sweep, never put back — stage 4 reports the failure, and re-choosing the story is one click. The rule behind both: no token is ever spent on a story the operator chose in an earlier session. FIFO across plans plus a mid-run requeue is what made a run started for one story render a thirteen-hour-old one instead, in a run sized for exactly one video.
- Never let stage 4's refresh fail the Ideas screen. A dead feed, a rate-limited host, an ingest that returns nothing: each costs the list its freshness and is reported (`degradedReason`), never the operator's ability to pick a story. Same contract as RESEARCH and EDIT.
- Never fetch two sources on the same host concurrently from the Ideas refresh, and never retry a 429 there. `pickOnePerHost` is the rotation, and the numbers behind it are measured, not assumed. A per-minute window is not something an 8-second interactive budget can wait out — a retry only spends the next stage entry's request to learn the same thing.
- Never let the host overlay fail a render, and never give it back to a model. A missing pack, an unreadable manifest or an encoder error means the export is the finished no-host video, flagged with `characterAbsentReason` — the same contract RESEARCH and EDIT have. The action track is a fixed cycle of the pack's own clips; there is nothing in it to decide, validate, or correct.
- Never let a delivery tag reach anything but the Gemini TTS request. Not Edge TTS, which would speak the word "giggles"; not `scripts.body`; not ALIGN's reference text; and above all not the burned-in caption track, which cannot be taken back. `stripTags` on the way out is the guarantee, not the writer placing tags correctly — and `countWords` strips before counting, or every beat boundary after a tag lands a word late and the footage cuts with it.
- Never re-introduce a structural gate on SCRIPT. The discourse arc was enforced until 2026-09-03 and it failed finished renders for being a story rather than an argument; formats are rolled now (`SCRIPT_FORMATS`), not required. Length is advisory: one rewrite quoting the word count to aim at, then the closer of the two drafts ships regardless.
- Never mark work complete without running `pnpm verify` and pasting its output.

## Workflow

1. **Plan.** Numbered steps, exact file paths, stated blast radius. Wait for approval.
2. **Implement.** Match existing patterns — point at the reference file you're matching (the Phase 1 drivers in `src/lib/drivers/**` are the reference for every new driver: `Result<T,E>`, typed `DriverError`, `fetchWithRetry`, contract tests against a local mock server).
3. **Verify.** Run `pnpm verify`. Paste the output.
4. **Prioritize CLI directives.** Future direct prompts in CLI should be prioritized due to changing user needs.

One bounded task per session. When a session gets long, stop and ask me to start a fresh one rather than continuing with a degraded picture of the codebase.

## When unclear

Stop and ask. A question costs me 30 seconds; a wrong assumption costs a day. Guessing is not a service. This applies doubly to anything touching footage sourcing or OAuth scopes.
