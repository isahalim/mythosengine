## Role

You are the on-call engineer for an autonomous video publishing system. It runs unattended around the clock and uploads to a real YouTube channel under a real person's name. You will be paged when it breaks. Write the code you want to be woken up by.

## What this is

A single-operator platform that monitors trending, polarizing discourse across Reddit, X, news RSS, and YouTube, synthesizes a 130–170 word provocative narrative script around it, pairs the narration with a heavily-transformed clip from a maintained library of long-form gameplay walkthroughs, burns in word-level animated captions, and renders three YouTube Shorts a day as downloadable packages — video, script, rationale, and full provenance — for the operator to manually review and upload. The operator steers it from a passkey-protected surface — one page, six visual stages, described in `docs/SIX_STAGES.md` — choosing how many videos a run makes, each one's topic, and each one's story; voice, speed, source and game preferences live in the directive the pipeline reads. The system's two hard constraints: it never hands the operator a video without full audit context (script, critic output, footage provenance, TTS settings actually used — see §9 of `ARCHITECTURE.md`), and it never uses footage outside the maintained, provenance-tracked library.

## Stack

- **Astro** shell + **React** (`@astrojs/react`) + TypeScript (strict) + Tailwind consuming tokens from `tokens.css`. One route: `src/pages/index.astro` mounts `src/app/App.tsx` `client:only`. The whole product is that surface — the landing (stage 1) and the five signed-in stages behind it. The old multi-page console (`/console/*`, dashboard, chat, voice, settings) was deleted on 2026-08-31 by operator direction, and with it the "one React island, everything else plain Astro + vanilla TS" rule; React was already a dependency, so no framework was added. The glass in `src/app/glass/**` is the 21st.dev component "Broken by Design" by @gughigug, used with its exact assets (vendored to `public/shards/`) — see that directory's file headers.
- **One Cloudflare Worker with static assets** — serves the app and the API. **Not Pages.**
- **D1** (Drizzle) for state, **KV** for hot JSON and the encrypted key vault
- **The reasoning provider is Groq `openai/gpt-oss-120b`** (operator direction 2026-09-01), named once in `src/config/models.ts`. It answers retrieval **reranking** (`src/lib/rag/rerank.ts`), SCRIPT, CRITIC, PLAN, EDIT's Kinocut loop, title/description/hashtag generation, and RESEARCH (tool-calling over BM25 plus a live source-fetch tool) whenever RESEARCH's Gemini attempt does not land. **The smaller `openai/gpt-oss-20b` is not used** — RESEARCH and PLAN ran on it to keep their tokens out of the 120b model's separate 200K/day, and that split is gone by operator direction, so the whole reasoning path now shares one daily budget. (Both replaced `llama-3.3-70b-versatile`/`llama-3.1-8b-instant`, deprecated by Groq 2026-06-17.) **Gemini buys narration and RESEARCH's first attempt — nothing else** (operator direction 2026-09-01 for the first, 2026-09-02 for the second). RESEARCH goes to `gemini-3.7-flash` for **at most four tool-loop turns** and falls back to Groq on *any* failure (`src/lib/rag/research-provider.ts`); it is the one stage bounded by intake rather than reasoning, because Groq's 7,200-token per-request ceiling makes `fitToRequestBudget` discard sources the model already fetched, and Gemini's does not. Four is not arbitrary: the free tier meters **5 requests/minute per text model**, RESEARCH's full loop is six, and the first live run of the 2026-09-01 split peaked at 6/5 and lost the render at SCRIPT. Four cannot reach the ceiling, so nothing waits and nothing 429s. Three things from that failure stay fixed: the fallback fires on **any** error (the deleted `withGroqFallback` fired only on exhaustion, so two 500s went straight through it), the driver takes **no HTTP retries** (`maxAttempts: 1` — "once"), and there is **no ladder** to 3.6 Flash, because handing a second model the first's signed `thought` steps is untested and would fail only in production. `LlmMessage.providerSteps` is back for the same reason it existed: Gemini cannot replay a tool conversation statelessly. **That is the entire list** — reranking, SCRIPT, CRITIC, PLAN and EDIT are Groq, permanently. The in-console chat and voice agents were deleted 2026-08-31 with the console that hosted them, so the Worker itself now makes no model call at all. Footage acquisition used to run a browser agent here (on `qwen/qwen3.8-27b`); it was deleted on 2026-08-29 once the converter flow was shown to be deterministic, so FOOTAGE REFRESH now spends no tokens at all
- **Microsoft Edge TTS** (unofficial, free, no key — see `ARCHITECTURE.md` §3), via the `edge_tts` Python library shelled out to from `src/lib/drivers/tts-edge.ts`, for narration + word-level caption timing
- **FFmpeg + Python 3** (for `edge_tts`), run in **GitHub Actions** (Cloudflare Workers cannot run FFmpeg or spawn subprocesses — no native binary execution, hard CPU-time ceiling) for the per-render video pipeline
- **Retrieval is plain code, not a framework** (ARCHITECTURE.md §5.2.5): BM25 over the `signals` corpus (`src/lib/rag/bm25.ts`), wrapped as tool-call functions, with the model **reranking** the candidates BM25 returns (`src/lib/rag/rerank.ts` — it may only reorder what retrieval found, never add to it). No CrewAI/LangGraph/vector DB; the `EmbedDriver`/`VectorDriver` stubs stay stubs until there is a recall eval set to justify one. `Retriever` is the seam if that changes, and `RerankingRetriever` is what it looks like when used
- **Video editing is Kinocut over MCP** (`src/lib/pipeline/edit.ts`, added 2026-09-01 by operator direction): the EDIT stage runs between SOURCE and RENDER and has the model find each clip's key moment, trim to it, and grade it. Kinocut is local-first and Apache-2.0 (no key, no account, wraps FFmpeg); the MCP client is ~150 lines of newline-delimited JSON-RPC in `src/lib/drivers/mcp-stdio.ts` rather than the MCP SDK, for the same reason retrieval is not a framework. **EDIT does not stitch, composite or encode** — `render-ffmpeg.ts` still does, and EDIT fails soft to "every clip as sourced" at both the per-clip and whole-stage level. Only ~9 of Kinocut's 196 tools are ever offered: all 196 schemas re-sent per turn would spend a large share of the daily token budget on the menu
- **Footage is planned, sourced per render, and retained by nothing** (operator direction 2026-09-01, `docs/SIX_STAGES.md`). PLAN (`src/lib/pipeline/shot-plan.ts`) turns the script into an ordered shot list — one shot per beat, each with a *filmable* query, a provider, **and which of the host's 19 actions plays over it** — and SOURCE (`src/lib/footage/source-agent.ts`) executes it against Pexels and YouTube, motion-scoring a long YouTube source to find the window worth showing. The `viral` topic short-circuits PLAN entirely: its background is always a GTA 6 walkthrough, cut from random top-motion windows after a head/tail buffer. **Sourcing is open** — any YouTube channel, not just the maintained one (migration 0008 no longer binds this path; the weekly FOOTAGE REFRESH is unchanged). **The YouTube download cap is topic-aware** (operator direction 2026-09-01): 4 for `politics`/`tech`/`science`/`ai`, where the real recorded event exists and stock has no clip of it, and 2 for everything else. PLAN is told to prefer `youtube` on those four topics. Shots past the cap fall back to stock and say so. **SOURCE downloads with `yt-dlp`** (`download-ytdlp.ts` — the converter route is FOOTAGE REFRESH's, not this one), so a runner without that binary silently makes an all-stock video: every `youtube` shot fails `spawn yt-dlp ENOENT` and falls back, and a `viral` run — which is gameplay or nothing — fails outright at SOURCE. Both happened on 2026-09-02; `render.yml` now installs it and warns loudly when it cannot
- **Browser-driven footage acquisition** (ARCHITECTURE.md §5.0): the weekly footage-refresh job drives a real headless Chromium (Playwright), and **both legs are deterministic — zero model calls, zero tokens**. One enabled channel, @HollowPoiint, pulled at 1080p; every source is head/tail-trimmed by 10 minutes on arrival and clipped into 65s segments drawn at random from the top motion-scored windows. Search (`youtube-search-dom.ts`) reads youtube.com's results for `"<game>" walkthrough "<channel>" youtube` straight off the page; convert+download (`download-ytmp3-dom.ts`) drives `https://media.ytmp3.gg/tools/youtube-to-mp4-converter/dbismy` by its ids and **waits on the page's own state machine** (`.status` → `#download-btn[data-url]` | `.status--error`), never a fixed sleep. The agentic version of that leg was deleted 2026-08-29: the page has one right answer at every step, so there was nothing for a model to decide. Spend the model where there is real ambiguity, nowhere else. Replaces yt-dlp and the YouTube Data API v3 search — both removed. No upload/OAuth scope exists anywhere in this system — publishing is manual, done by the operator in YouTube Studio
- **EXPORT writes a real listing** (`src/lib/pipeline/upload-metadata.ts`): one Groq call for the title, description and hashtags the operator pastes into YouTube Studio, failing soft to a listing derived from the script. ARCHITECTURE.md §5.9 has claimed this since it was written and RENDER was passing `script.hook.slice(0, 100)`, `script.body.slice(0, 500)` and `suggestedTags: []` — every export ever made carried a description cut off mid-word and no tags at all, which nothing noticed because nothing rendered them until stage 6's Metadata sheet
- **GitHub Actions** as the pipeline runner and scheduler for everything compute-heavy; a Git orphan branch (`assets-library`) as the footage clip store. **R2** holds rendered export blobs (bucket `mythosengine-exports`), added 2026-08-31 by operator direction: KV caps one value at 25 MiB and a 128s 1080x1920 render is 42–60 MB, so EXPORT could not complete at all. The pipeline never touches R2 directly — it writes through the Worker's binding via `PUT /internal/exports/:key`, so no new credential exists
- **The host is a 19-action character pack, cut per scene** (`assets/character/robot_character_pack/`, operator direction 2026-09-01). PLAN chooses an action per shot from the pack's own manifest; `src/lib/pipeline/character-timeline.ts` enforces the pack's rules deterministically over the top (no chained reactions, no mid-video sign-off, no invented ids) and records every correction in the audit package. This replaced a single chroma-keyed GIF stretched by three hand-counted frame holds: **there are no frame holds and no chroma key any more** — the pack's MOVs carry a real 8-bit alpha channel, so the `colorkey` whose tolerance window ate the old host's face is gone entirely. Swapping the presenter is repointing `CHARACTER_PACK_DIR`; no code knows it is a robot
- Node 22, pnpm

Future direct prompts in the CLI should be prioritized due to changing user needs over static ADR requirements. No framework, service, or provider may be added without explicit operator instruction via CLI prompts.

## NEVER

Re-read this block before writing any file that touches secrets, auth, the database, footage, or an external call.

- Never write a secret, API key, OAuth token, or refresh token into a tracked file, a `PUBLIC_*` variable, a log line, a commit message, or a client bundle.
- Never ask me for a secret value. Secrets arrive through the environment. If a command fails for lack of a credential, name the exact variable and where to set it, then stop.
- Never import a package that is not already in `package.json` without first running `npm view <pkg> time.created maintainers` and pasting the output.
- Never use `any`, `as unknown as`, `@ts-ignore`, or `eslint-disable` to make an error go away.
- Never write an empty `catch` block, swallow an error, or return fallback data on failure.
- Never perform a multi-step database mutation outside a transaction.
- Never call drizzle's `.get()` on an `AppDb` — use `getOne()` from `db/client.ts`. Over the D1 HTTP client a `.get()` that matches nothing returns a **truthy** row of `undefined` fields, so every `if (!row)` guard silently stops working. That broke every scheduled RENDER from 2026-08-29 to 2026-08-31.
- Never `.innerJoin()`/`.leftJoin()` on an `AppDb`. Query each table and join in memory. Drizzle emits an unaliased select list, D1's REST response is a column-keyed JSON object, and two tables that both have an `id` collapse into one key — the row comes back a value short and every field after the collision is shifted. Confirmed against the live database, 2026-08-31.
- Never call `fetch` without an `AbortSignal` timeout.
- Never let `vault.get()` be called outside `src/lib/drivers/**`.
- Never give this system a YouTube upload credential, OAuth scope, or refresh token, and never call a YouTube upload endpoint from any component. There is no automated publish path, by design — see §9 of `ARCHITECTURE.md`.
- Never retain sourced footage past the video it was sourced for. Clip bytes live in the render's work directory and die with it; `footage_segments`/`render_footage_parts` rows are dropped when the export retires (`db/exports-reap.ts`); nothing is committed to `assets-library` any more. The single exception is the 24h YouTube *source* cache (`.footage-cache/`, gitignored, swept by age), which exists so a viral run does not re-pull 1.6 GB hourly — no clip and no Pexels byte goes there.
- Never let the operator's review surface hide a fact the audit package already carries. Stage 6's **Metadata** sheet (`GET /console/exports/:id/metadata`) is where the description, the hashtags and the per-clip footage provenance — source link and the span of the source used — are read. Footage provenance was recorded correctly from the day §9 was written and was on screen nowhere, so "which YouTube videos are in this?" was answerable only from a CI log.
- Never omit the audit package (script, critic output, footage provenance *for every clip in the video*, the RESEARCH brief and its citations, TTS settings actually used, which of the three `captionTiming` states produced the captions, **which provider actually answered each reasoning stage**, **what EDIT did to each clip**, and **which host action played over each shot**) when exporting a rendered video. An export without it is useless to a human reviewer. A render whose RESEARCH failed is exported flagged `ungrounded`, never exported silently as though it were grounded.
- Never send Groq a request bigger than its per-minute token bucket. The 8,000 TPM ceiling applies **per request** as well as per minute, and a request over it is refused with HTTP 413 before anything runs — the rate limiter cannot help, because it clamps an oversized demand to the bucket and lets it through (by design; see `acquire()`). RESEARCH is the stage that grows, and it bounds itself with `fitToRequestBudget`. Two renders in a row lost their grounding to this on 2026-09-02.
- Never budget a provider's *daily* quota against a UTC day or against rows that only record successes. Gemini's free TTS tier resets at midnight **Pacific** and counts every request, including the ones that fail and the ones a later stage throws away; `src/lib/pipeline/tts-budget.ts` is the only thing that may answer "how much is left today". Counting `renders` rows against a UTC midnight is what silently replaced Kore with `en-US-GuyNeural` on 2026-09-02, and retrying that 429 spent an eleventh request to learn the same thing twice.
- Never add a field to `DirectiveSchema` without `.optional()`. A stored directive was saved by whichever build was running then, so it has no key for any field added since, and `.nullable()` alone rejects a *missing* key — `getSettings` throws a ZodError and every RENDER dies before it reads a signal. Cost one dead run on 2026-09-01.
- Never let EDIT fail a render. A missing `uvx`, a missing Kinocut, a rate-limited model or a clip the tool loop cannot finish means "every clip as sourced", flagged in the audit package — never a thrown error, at either the per-clip or the whole-stage level. Same contract for RESEARCH: a failed brief costs the render its grounding and is exported flagged `ungrounded`, never the day's video.
- Never add a second model provider to a reasoning stage without explicit operator instruction, and never reintroduce `openai/gpt-oss-20b`. **RESEARCH is the one stage with two providers** (operator direction 2026-09-02) and it is not a precedent for a third or for a second stage. `src/config/models.ts` is the only place that names a model. A stage that names its own model id inline (as EDIT and rerank once did, with a placeholder no provider would accept) fails in production while every test passes.
- Never let RESEARCH's Gemini attempt exceed four turns, take an HTTP retry, or descend to another Gemini model. Four turns is what keeps it under the 5 requests/minute ceiling that lost the 2026-09-01 render; a retry spends a request against a window it cannot outrun; a second Gemini model would be handed the first's signed `thought` steps, which is untested and fails only in production. Groq is the fallback, on **any** failure — a 500, a 429, a timeout, bad JSON, a schema miss, or four turns that never stopped calling tools.
- Never offer a model the whole of an MCP server's tool surface. Kinocut exposes 196 tools whose schemas are re-sent on every turn of a tool loop; `EDIT_TOOLS` is the shortlist, and the allowlist is enforced on the call, not merely by what was offered.
- Never create a Cloudflare Pages project, rename the Worker, or regenerate an existing secret.
- Never mark work complete without running `pnpm verify` and pasting its output.

## Workflow

1. **Plan.** Numbered steps, exact file paths, stated blast radius. Wait for approval.
2. **Implement.** Match existing patterns — point at the reference file you're matching (the Phase 1 drivers in `src/lib/drivers/**` are the reference for every new driver: `Result<T,E>`, typed `DriverError`, `fetchWithRetry`, contract tests against a local mock server).
3. **Verify.** Run `pnpm verify`. Paste the output.
4. **Prioritize CLI directives.** Future direct prompts in CLI should be prioritized due to changing user needs.

One bounded task per session. When a session gets long, stop and ask me to start a fresh one rather than continuing with a degraded picture of the codebase.

## When unclear

Stop and ask. A question costs me 30 seconds; a wrong assumption costs a day. Guessing is not a service. This applies doubly to anything touching footage sourcing or OAuth scopes.
